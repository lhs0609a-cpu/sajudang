## 1. 시스템 개요

```
[클라이언트]  Next.js (웹 + 모바일웹 동일 코드, 반응형)
      ↓ REST / JSON
[API]        FastAPI (Python)
      ↓
[계산엔진]    sxtwl + 자체 명리 로직        ← 서버 전용, 절대 클라 노출 금지
[문장엔진]    조건부 뱅크 조합              ← 서버 전용
[DB]         PostgreSQL + pgvector
[캐시]        Redis
[스토리지]    S3 호환 (에셋·리포트 PDF)
```

### 왜 계산이 Python 서버인가

- 절기 정밀 계산 라이브러리(`sxtwl`)가 Python
- 문장 뱅크가 클라이언트에 노출되면 그대로 복제됨
- 참조 구현체(`sajudang.html`)는 클라 계산이지만 **프로덕션에서는 서버로**

## 4. 핵심 자료구조

### 4-1. Feature Store (모든 해석의 원천)

```python
class Features(BaseModel):
    # 명식
    pillars: list[Pillar]          # 4주 (년월일시)
    day_gan: str                   # 일간 — 이 사람 자신
    day_ji: str
    hour_known: bool               # ★ 시주 입력 여부

    # 파생
    elements: dict[str, float]     # 오행 5 (지장간 가중)
    strength: Literal["신강","중화","신약"]
    strength_score: int
    yongsin: str
    ten_gods: dict[str, int]       # 십신 10
    strong_el: str
    weak_el: str
    gap: float                     # 최강-최약
    flow: Literal["비겁","식상","재성","관성","인성"]
    flow_el: str
    top_ten_god: str

    # 시간
    daeun: list[Daeun]
    daeun_now: int                 # 인덱스
    daeun_ten_god: str
    age: int

    # 관계
    ilji_chung: bool
    ilji_hap: list[str]

    # 보정 내역 (투명성 패널용)
    correction: Correction
```

> `hour_known=False` 이면 **시주를 계산에서 제외**합니다.
> 오행·십신·일지충 판정을 3주로만 수행. 이것을 어기면 없는 정보를 지어내는 것이 됩니다.

```python
class Lens(BaseModel):

```

## 5. API 명세

### POST /v1/chart
명식 산출. **가장 많이 호출되는 엔드포인트.**

```jsonc
// 요청
{
  "year": 1993, "month": 5, "day": 15,
  "hour": 10, "minute": 20,          // hour_known=false 면 null
  "hour_known": true,
  "sex": "F",
  "birth_city": "서울"               // 진태양시 보정용
}
// 응답
{ "chart_id": "...", "features": { ...Features }, "cached": false }
```

캐시 키 : `sha256(year|month|day|hour|minute|hour_known|sex|city)`
TTL : 무기한 (같은 입력 = 같은 결과)

### POST /v1/hook
무료 훅 5단 생성.

```jsonc
{ "chart_id": "...", "concern": "love", "axis4": "INFP" }
→ { "segments": [ {stage, label, source, html, question, yes, no, statement_id} ] }
```

`statement_id` 는 응답 기록용. **문장 원문은 서버에만 두고 렌더된 HTML만 내려보냅니다.**

### POST /v1/report
유료 리포트 생성.

```jsonc
{ "chart_id": "...", "lens_id": "pungun", "tier": "all", "concern": "love" }
→ { "report_id": "...", "cuts": [...], "locked": [...] }
```

`tier=one` 이면 `locked` 에 나머지가 남습니다.

### POST /v1/relay
릴레이 추천.

```jsonc
{ "chart_id": "...", "read": ["pungun"], "skipped": [] }
→ { "recommend": [ {lens_id, reason, quote, price, priority} ],
    "forced": ["dongja"],           // 정서 안전망
    "bundle": {...},
    "blocked": false }              // 세션 2명 초과 시 true
```

### POST /v1/feedback
응답 기록. **hit율 데이터의 원천.**

```jsonc
{ "statement_id": "...", "chart_id": "...", "answer": 1 }
```

### GET /v1/daily
오늘의 일진.

```jsonc
{ "chart_id": "..." }
→ { "gz": "丙寅", "relation": "눌리는", "score": 44, "text": "...", "free": true }
```

## 7. 보안·비노출

**클라이언트에 절대 내려가면 안 되는 것**

```
· 문장 뱅크 원문 (STAB / IGNITE / BLAME / NAME2 …)
· 렌즈 프롬프트·금지어 목록
· 릴레이 규칙 조건식
· 만세력 계산 로직
```

렌더된 HTML만 내려보내고, 원본은 서버에 둡니다.
참조 구현체는 전부 클라에 있으니 **그대로 배포하면 안 됩니다.**

## 8. 금지어 필터 (출력 후처리)

```python
BLOCK = [
  r"반드시.{0,10}(옵니다|됩니다|합니다)",
  r"(이혼|파혼|사망|요절)(합니다|한다|할 것)",
  r"(암|당뇨|우울증|공황)",           # 질병명 전반
  r"과학적으로|통계학|적중률\s*\d+%",
  r"\d+월까지 기다리",
  r"(수술|출산).{0,6}(날|택일)",
]
```

- LLM 도입 시 **출력 후처리로 반드시 통과**
- 위반 시 재생성 1회 → 실패하면 안전 문장으로 대체
- 위반 로그를 남겨 프롬프트 개선에 사용
