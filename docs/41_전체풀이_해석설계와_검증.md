# 전체 풀이: 근거를 연결하는 해석 계층

2026-09-13 구현. 기존 만세력 정책과 명식 값을 유지하면서 해석 선정, 전체 편집, 상황 답변과 검수 경로를 추가했다.

## 사용자에게 달라지는 것

- 캐릭터 표지와 본문에서 이번 고민의 핵심 해석을 먼저 읽는다.
- 각 결론은 강점이 되는 조건, 확인할 장면, 반복되는 비용, 예외와 행동을 함께 제공한다.
- 근거를 펼치면 실제 기둥 위치, 십신 집계, 연결된 기존 패턴 조건과 우선 선정 이유를 확인한다.
- 답변에서 경험과 다르다고 선택하면 해당 결론을 종합 해석에서 제외한다. 제외한 내용을 별도로 보여주며, 다른 영역에서도 같은 가설을 되살리지 않는다.
- 지금 문제와 이미 해본 시도 여부에 따라 선택 비교와 마지막 행동이 바뀐다.
- `all` 또는 `sub` 구매자는 캐릭터 표지/본문의 링크로 `/omnibus`에서 종합본을 읽는다. 실제 권한은 API의 주문 기록으로 확인한다.
- 동일한 가설은 한 번 설명하고 다른 영역에서는 적용할 장면과 질문을 추가한다. 캐릭터별 고유 관점은 부록에 둔다.

## 해석 선정 규칙 v1

1. 명식에서 천간(일간 제외)과 지지 본기를 분리해 집계한다. 나머지 지장간은 별도로 보존하며 주도 십신 집계에 중복해서 더하지 않는다.
2. 현재 고민에 관련되고 두 십신 묶음이 실제로 함께 있는 관계만 후보로 만든다. 기존 `pattern.py`의 성립 조건이 맞으면 그 조건과 근거를 추가한다. 기존 패턴의 사건 추정 문장은 이 계층에 가져오지 않는다.
3. 두 축의 수, 천간 노출, 기존 관계 규칙과의 연결, 시각 민감도와 사용자 답변을 바탕으로 우선순위를 정한다. 가중치는 편집용 휴리스틱이며 신뢰도나 사건 확률이 아니다.
4. 같은 관계를 의미 키로 중복 제거하고, 이미 설명한 축의 반복을 감점해 최대 3개를 선택한다. 해당 후보가 부족하면 3개를 억지로 채우지 않는다.
5. 사용자가 `no`로 답한 가설은 제외한다. `mixed`는 상황에 따른 예외를 추가한다. `yes`는 사용자가 고른 경험으로 표시하고 계산 근거와 구분한다.
6. 구조 검증은 존재하지 않는 근거, 성립하지 않는 관계, 중복 가설, 제외한 가설의 재선정, 예외·행동 누락을 거절한다. 출력은 기존 guard를 통과한다.

원국 가설은 현실 행동을 증명하지 않는다. 명리 전문가의 해석 체계 검토와 고객 평가는 별도다. 단순한 두 축 관계가 충분하지 않은 사례는 검토 자료에서 빈 핵심 결론으로 드러나게 했다.

## 용신·시기·시각 미상

기존 신강약 점수와 억부용신 선택값을 바꾸지 않는다. 선택에 사용한 후보와 가중치, 동률과 중화일 때의 복수 가능성, 조후·격의 성패·합화가 최종 판단에 포함되지 않았다는 범위를 보여준다. 전문가 승인 없이 새로운 유파의 가중치를 공식 계산에 넣지 않는다.

대운은 기존 연 나이를 사용한다. 첫 대운 진입 전과 계산 목록 이후를 현재 대운으로 확장하지 않는다. `Features.as_of` 기준일을 추가했으며, 세운·월운은 해당 날짜 00:00 KST를 기준으로 기존 sxtwl 절입 함수와 오호둔을 사용한다. 현재·다음 사주년과 현재부터 3개 절월을 보여준다. 출생지 보정을 현재 달력에 다시 적용하지 않는다. 미래 사건의 확률이나 투자·관계의 실행 시점을 제시하지 않는다.

시각 미상일 때 실제 명식은 여전히 세 기둥이다. 입력 날짜와 도시에서 매 시계 분을 가정한 계산을 별도로 수행하고, 서로 다른 명식별로 두 축의 공존 조건·강약·용신·일주의 변화만 비교한다. 시나리오 시주는 실제 명식으로 저장하지 않는다. 가능한 분의 개수는 출생 시각의 확률이 아니다. 계산 불가능한 분은 누락 개수를 표시한다. 결과는 입력 조합별 제한된 캐시에 보관한다.

기존 캐시의 기준일은 이미 검증된 `chartdate` 기록으로 보완한다. 다시 계산하는 요청에서는 `as_of`와 시각 민감도 필드가 없는 캐시를 갱신한다. 명식 키와 계산 정책은 유지한다.

## API와 권한

`POST /v1/report`의 `reading`은 서버가 확인한 티어에 맞춰 투영한다.

| 티어 | 새 해석 범위 |
|---|---|
| free | 핵심 결론 최대 1개, 구조·용신의 판단 범위, 상황 질문 |
| one | 선택한 고민의 결론 최대 3개, 두 선택 비교, 대운, 실행·재점검 |
| sub | one 수준의 깊이, 전체 캐릭터와 영역별 종합본 |
| all | 전체 종합본과 세운·절입 기준 월운까지 |

`POST /v1/omnibus`는 기존 주문·열람·환불 검사를 유지한다. 이전 구현에서 `sub`에도 강제로 `all` 리포트를 조립하던 경로를 실제 승인 티어에 맞췄다.

`consensus.counts`의 단위는 `영역`이다. 동일한 관계 가설이 6개 영역 중 몇 곳에서 선택됐는지 세며, 캐릭터별 첫 번째 컷이나 독립된 전문가들의 합의로 설명하지 않는다.

답변 형식:

```json
{"extras":{"consultation":{"concern":"work","answers":{
  "claim:work:learning_output":"no",
  "driver":"role",
  "stage":"tried"
}}}}
```

고민과 질문·선택 ID를 서버에서 검증한다. 다른 고민의 답이나 임의 문자열은 반영하지 않고 입력 오류를 표시한다. 답변은 리포트 생성 요청 메모리에서만 사용하며 원국이나 DB에 저장하지 않는다. 화면의 명식·고민·캐릭터가 바뀌면 입력 상태도 초기화한다. 빈 `answers`로 선택을 지울 수 있다.

## 남는 검증 범위

- 사람에 의한 명리 규칙 검수와 실제 가격을 제시한 고객 비교 평가는 자동으로 대신할 수 없다. 생성된 30건 자료와 빈 평가표로 진행해야 한다.
- 기존 캐릭터 문장 뱅크의 모든 문장을 새 주장 구조로 변환한 것은 아니다. 기존 상세 풀이와 캐릭터 부록은 유지하며 새 종합 해석을 먼저 제공한다.
- 이번 렌더러는 서버 문장 뱅크 기반이다. 외부 언어모델을 호출하지 않는다. 향후 모델을 연결할 때도 승인된 주장 ID·근거와 예외를 유지하고, 새로운 숫자·사건을 생성하지 않도록 별도 검증이 필요하다.
- 계산 정책·유파를 바꾸는 정밀화는 전문가 검수와 명식 마이그레이션을 전제로 별도 버전으로 진행한다. 이번 변경은 기존 계산의 한계를 숨기지 않고 대안·범위를 표시한다.
# 개인별 문장 분기 보강 (해석 버전 2)

실제 샘플 검토에서 십신 두 묶음의 공존만 확인한 뒤 고정 조언을 붙이는 한계가 드러났다. 특히 식상 4·인성 2인 명식에 준비 때문에 실행을 미룬다는 설명을 붙였고, 재성의 지장간이 있는데도 돈 영역은 비어 있었다.

`engine/personal_reading.py`를 통해 다음을 보강했다.

- 열 가지 관계 규칙 모두 두 묶음의 비중 방향에 따라 결론·실행을 다르게 고른다. 같은 수의 균형 사례는 기존 관계 문장을 유지한다.
- 천간·본기 집계와 나머지 지장간을 분리하고, 천간의 동일 십신 반복·월지 본기·일지 본기·십신 동률을 본문에 드러낸다.
- 열 가지 십신의 해석을 구분한다. 다섯 묶음별 여섯 영역의 장면을 별도로 두고, 실제 대상 영역의 위치 근거와 연결한다.
- 재성·관성의 겉 집계가 0이어도 지장간을 확인한다. 이를 재산이나 직업의 부재로 옮기지 않는다.
- 대운·세운·월운의 천간이 원국의 어떤 비중에 더해지는지 설명하고, 지지의 합·충·반복을 실제 만나는 궁위와 연결한다.
- 상담에서 해석을 거절하면 별도 성향·영역 문장으로 재포장하지 않도록 해당 확장을 보류한다.

검증은 `tests/test_personal_reading.py`의 실제 샘플, 반대 비중 비교, 인접 출생 시각, 지장간, 거절 반영, 원국과 운의 상호작용 검사 및 기존 회귀 검사로 수행한다. 이는 편집 로직의 검증이다. 명식으로 실제 개인의 성격이나 경험을 알아냈다는 검증은 아니며 전문가·고객 평가 결과는 여전히 없다. 문장 체계는 규칙 기반이며 모든 사람에게 독자적인 산문을 생성하는 방식은 아니다. 기존 캐릭터 부록 전체의 문장 재작성은 이 변경에 포함되지 않는다.
# 쉬운 말과 캐릭터 목소리 (해석 버전 3)

`reading_narrator.py`는 계산·선택된 관계를 바꾸지 않고 독자에게 보이는 본문을 작성한다. 관계별 생활 비유와 비중 방향별 변형을 두며, 장면 → 쉬운 뜻 → 생기는 어려움 → 애쓴 부분 → 작은 행동 순서로 쓴다. 모르는 개인의 과거·상처·감정을 사실처럼 만들어 넣지 않는다.

본문은 하오체로 작성하고 기존 말투 엔진으로 캐릭터별 변환한다. 첫마디는 스무 캐릭터별로 다르다. 9월 13일 사용자 요청에 따라 이전의 전원 하오체 설정을 변경했다. 도령은 하오체, 홍매파는 반말, 훈장·노파는 하게체, 은별·월하·약초·청동자는 해요체, 연담·화경은 합쇼체를 쓴다. 제목에도 말투 변환을 적용한다.

숫자·한자·선택 이유·예외는 ‘왜 이렇게 읽었나요?’에 보존한다. 시각 미상이나 시주 경계처럼 해석에 직접 영향을 주는 조건은 본문에도 남긴다. 종합 책의 캐릭터 부록은 같은 선택된 해석을 각자의 목소리로 말하며, 상충할 수 있는 예전 성향 컷을 다시 붙이지 않는다. 캐릭터 상세 페이지의 기존 전문 해설은 별도 펼침 영역에서 읽는다.

`test_reading_narrator.py`는 스무 캐릭터 × 여섯 고민의 보이는 본문에서 전문 용어·한자·긴 문장을 검사한다. 말투 및 제목의 차이, 동일 근거 유지, 비중 방향에 따른 비유 변경, 거절 반영, 무료 권한, 접힌 근거 보존도 확인한다. 실제 초등학생의 이해도나 감동을 보장하는 검사는 아니며 독자 평가가 별도로 필요하다.

# 이야기 연결과 실제 경험 확인 (해석 버전 4)

`reading_storyline.py`에서 중심 해석 → 생활 속 어려움 → 확인한 사정 → 작은 행동 순서로 이야기를 연결한다. 열 가지 십신 × 여섯 고민의 장면 60개를 분리하고, 동률·월지·일지·드러난 것과 숨은 것·강약·시각 미상을 반영한다. 같은 근거 구조라면 문장이 반복될 수 있으며, 생일마다 무작위 표현을 붙여 개인화한 것처럼 보이지 않는다.

`reading_context.py`는 생활 장면에 동의한 뒤에만 이유를 묻는다. 스스로 원함·걱정·외부 요구·모름 중 실제로 답한 사정에 따라 설명과 행동을 바꾼다. 외부 요구라고 답하면 그 일을 성격 탓으로 해석하지 않는다. 답변을 거절하거나 지우면 해당 설명을 제거하며, 상담 이유는 별도로 저장하지 않는다. 무료 본문도 위로와 행동까지 마무리한다.

본문 뒤 선택형 평가에서 이해도·개인적 공감·위로·실행 가능성을 묻는다. 기본 선택이나 자동 제출은 없다. `/v1/reading-evaluation`은 이름·생년월일·상담 이유·원문 식별자를 저장하지 않으며, 브라우저/명식/캐릭터/버전의 해시 키로 중복 답변을 갱신한다. 90일 보관하며 결제 여부는 서버 주문으로 판별한다. 관리자 인증이 필요한 `/v1/admin/reading-evaluation`에서 버전별 응답 수를 확인한다. 이는 자발적 독자 의견이며 적중률이나 구매 전환율이 아니다.

검토 도구는 30개 합성 명식의 여섯 고민을 검사하고, 본문의 전문 용어 노출과 동일한 인물 소개·고민 본문을 별도 표시한다. 빈 사람 평가표에 쉬운 정도·이해받은 느낌·반복 구절·가장 개인적이었던 구절을 추가했다. 전문가와 실제 독자 평가, 실제 가격을 제시한 구매 의향 조사는 아직 실시하지 않았다.
