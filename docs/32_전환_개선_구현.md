# 전환 감사 후 개선 구현 · 2026-09-09

## 변경

- 무료 상세의 기본 화면을 요약·근거 한 줄·오늘의 행동으로 축약했다. 전체 무료 본문은 명시적인 펼치기에 보존했다. 가격 확인 버튼을 긴 본문 앞에 배치했다.
- 훅 5개에 응답하지 않고 요약으로 이동할 수 있다. 건너뛰기를 동의로 기록하지 않는다. 피드백 저장 요청이 늦어져도 다음 질문이 열린다. 중복 클릭을 방지했다.
- 부정 응답을 명식·고민·해석자 단위로 저장한다. 뒤의 요약에서 거절한 대목을 명시하고, 경험과 다른 점을 확인하는 행동과 입력 수정/다른 관점 경로를 제공한다. 새로고침에도 유지하며, 다른 명식·고민·인물의 피드백을 섞지 않는다. 원래 계산 결과를 사용자의 답에 맞춰 바꾸지 않는다.
- 결제 가능 상태는 `/api/sales-status`에서 판매자 정보와 API 결제 설정을 결합한다. 판매자 미등록, 결제 서비스 미설정, 일시 장애를 구분한다. 판매 불가 시 준비 주문을 만들지 않는다. 일시 장애와 주문 조건 요청 실패에는 재시도를 제공한다.
- 유료 상품의 열람 범위·추가 입력 조건·실제 미리보기를 앞으로 배치했다. 추상적인 목차와 ‘값이 오를수록 깊이’ 문장을 제거했다. 추가 질문을 이해할 수 있는 하오체 질문으로 바꾸고 잘린 예시에는 본문 일부임을 표시했다.
- 헤드라인·훅 안내·환불 안내·추천 예외 문구의 말투를 정리했다. 잘못된 조사 ‘풍운도령가’가 들어 있던 무료 상세 서술을 제거했다. 좁은 화면의 제목과 여백을 조정했다.
- 자동화 브라우저, 관리자, `?qa=1` 세션은 전환 이벤트와 결제의 분석 식별자에서 제외한다. QA 모드는 탭 세션에 유지한다. 유입 경로는 숫자 분류만 보내며 원본 URL·검색어를 저장하지 않는다.
- 관리자에 기기·유입·신규/재방문별 7일 관찰 완료 코호트의 서버 승인 전환율을 제공한다. 미완료 표본과 미수집 분류를 별도 표시한다. 미도달·낮은 응답률을 실제 이탈 원인으로 단정하던 CLI 설명을 수정했다.
- Fly 최소 실행 인스턴스를 1개로 설정해 첫 요청의 자동 재개 대기를 줄인다. DB를 무리하게 복제하거나 1만 동시 접속 성능을 보장하지 않는다. 부하 도구가 실패한 리포트를 완료 방문으로 세던 오류를 수정했다.
- 배포 후 무료 서비스 준비와 유료 판매 준비를 구분하는 `tools/release_readiness.py`를 추가했다.

## 검증 범위

격리 API와 프로덕션 웹 빌드에서 320/390/1920px, 건너뛰기·긍정·부정·판매 준비·설정 완료 모의·일시 장애 복구의 6개 흐름을 검사했다. 정상 요약은 약 500자, 모바일 기본 페이지는 1.6~1.9개 화면 높이였다. 이전에는 약 7,300자, 15~18개 화면 높이였다. 접은 본문을 포함한 총 콘텐츠를 삭제한 것은 아니다.

설정 완료/일시 장애 검사는 판매 상태와 PG 준비 응답을 모의했다. 실제 카드 결제는 실행하지 않았다. 운영 판매 활성화는 실제 사업자 정보가 들어와야 완료할 수 있다. 운영과 로컬의 상호·대표·등록번호·통신판매업 번호·주소·전화가 비어 있어 정보를 요청했다. 미등록 상태를 우회하거나 임의 정보로 채우지 않았다.

전체 테스트에서 이번 변경에 따른 문구·생성 스냅샷 실패를 수정했다. 기존 초상 원본의 머리 위치·상단 잘림 검사 3건은 별개로 남아 있다(`tests/test_bust_align.py`). 원본 7개는 상단 알파 영역이 0에 닿으므로 CSS 여백만으로 원래 그림을 복원했다고 할 수 없다. 이번에 이미지를 재생성했다고 주장하지 않는다.

최종 코드 검사 결과: 초상 정렬 파일을 제외한 전체 회귀 **1,277개 통과, 2개 건너뜀**. Next 프로덕션 빌드와 타입 검사 통과. 초상 검사 파일은 앞선 전체 실행에서 3건 실패를 확인했으며 이 결과를 통과로 계산하지 않았다.

실제 고객의 만족도·구매 의향·수정 후 전환율은 아직 검증되지 않았다. 고정된 일진 분류를 개인별 고유 예언으로 표시하거나, 내부 강약/연출 점수를 정확도 또는 예상 결제율로 표시하지 않는다.

## 재현

```text
python -m pytest tests --ignore=tests/test_bust_align.py -q
node node_modules/typescript/bin/tsc --noEmit -p apps/web/tsconfig.json
python tools/verify_conversion_improvements.py
python tools/release_readiness.py
```

브라우저 도구는 기본적으로 3029 포트의 로컬 빌드와 8029 포트의 격리 API를 사용한다. `SJD_AUDIT_WEB`으로 배포 웹을 지정해도 데이터/API 요청은 격리 서버에 보내며 PG 도메인은 차단한다. 결과는 `out/conversion-improvements/browser/results.json`에 저장한다.

실결제 활성화 후에는 결제 승인→주문 상태→유료 접근권→새로고침/구매 복원과 환불을 실제 PG 환경에서 확인해야 한다. 이후 QA를 제외한 7일 코호트로 변화와 환불을 함께 관찰한다.
