# 성신당 유료 가치 연구와 페이지·결과 평가

## 1. 판단의 출발점

성신당의 유료 가치는 개인의 고민에 맞는 설명을 이해하고, 맞지 않는 해석을 바로잡고, 읽은 뒤 자기 생활에 사용할 것을 얻는 데 두어야 한다. 글의 길이, 캐릭터 수, 강한 표현의 빈도만으로 그 가치를 판정할 수는 없다. 특히 내부 자동 점수와 실제 구매자의 평가를 같은 숫자로 보여주면 개선 방향을 잘못 잡을 위험이 있다.

연구 검토와 코드 감사의 결론은 세 가지다. 첫째, 개인화는 생년월일에 따라 단어가 바뀌는 정도를 넘어 사용자가 확인한 상황에 따라 설명과 조언이 달라져야 한다. 둘째, 읽는 과정의 부담과 결제 조건의 불확실성도 내용의 가치에 영향을 줄 수 있으므로 결과 문장만 고쳐서는 충분하지 않다. 셋째, 실제 독자의 이해·공감·실행·가격 대비 평가를 수집하기 전에는 구매 만족도를 점수로 단정할 수 없다.

이번 문서는 공개 연구에 근거한 설계 판단, 실제 구현을 검사한 내부 점수, 앞으로 수집할 사용자 응답을 구분한다. 문헌을 성신당에 적용한 판단은 설계 가설이며, 국내 사주 서비스에서 같은 효과 크기가 나타난다는 검증 결과는 아니다. 조사 기준은 2026년 9월 13일이며 공개 웹 자료와 저장소 코드를 대상으로 했다. 유료 경쟁 상품의 전문이나 실제 고객의 비공개 데이터를 확보한 것은 아니다.

## 2. 구매 가치와 관련 있는 근거

### 이해할 수 있는 내용

NN/g의 모바일 읽기 연구에서는 쉬운 짧은 글의 이해도가 모바일과 컴퓨터에서 실질적으로 크게 다르지 않았지만, 어려운 글은 읽는 속도를 늦췄다. 모바일이라는 이유만으로 내용을 과도하게 줄이기보다, 어려운 개념과 불필요한 설명을 줄이고 필요한 깊이는 선택해서 읽게 하는 편이 적절하다. 이 연구는 한국어 사주 문장이나 초등학생의 이해도를 검증한 연구가 아니므로, 문장 길이만으로 학년 수준을 주장해서는 안 된다.[^1]

점진적 정보 공개는 자주 필요한 핵심과 드물게 필요한 세부를 나누는 설계 원칙이다. 중요한 것은 무조건 접는 것이 아니라 무엇을 먼저 보여줄지 결정하는 일이다. 성신당에서는 생활 장면과 선택할 행동을 앞에 두고, 한자·개수·전통 용어·상세 계산은 이름이 분명한 펼침 영역에 둔다. 시각 미상이나 시주 경계처럼 해석 범위에 영향을 주는 입력 조건은 본문에도 남긴다.[^2]

### 개인화와 신뢰

개인화와 사용자 직접 설정은 모두 사용자의 필요에 맞는 경험을 제공하기 위한 수단이지만, 기본 사용성이 나쁜 서비스의 문제를 대신 해결하지는 못한다. 성신당에서는 계산된 명식에 따른 구분과 사용자가 직접 고른 상황을 분리한다. 생년월일만으로 알 수 없는 동기·상처·실제 사건을 사실처럼 덧붙이는 것은 개인화의 증거가 아니다.[^3]

신뢰 관련 사용성 연구에서는 정돈된 구성, 사전 정보 공개, 충분하고 최신인 설명, 외부에서 확인할 수 있는 정보가 반복적으로 중요하게 나타났다. 특히 가격과 포함 내용 같은 기본 정보를 얻기 위해 먼저 과도한 정보를 입력해야 하는 경험은 불신을 만들 수 있다. 이는 결제 전에 실제 본문 일부와 포함 범위·추가 입력·결제 주기를 보여주는 설계의 근거가 된다.[^4]

모호한 성격 설명을 자기에게 특별히 맞는 설명으로 받아들이는 현상은 개인적 공감과 해석의 타당성을 구분해야 하는 이유다. 공감이 높다는 응답은 유용한 고객 경험 데이터지만, 그 자체가 명리 규칙이나 미래 예측의 정확성을 입증하지는 않는다. 따라서 ‘나를 잘 아는 것 같음’과 ‘실제로 확인한 경험’, ‘근거를 따라갈 수 있음’을 별도로 평가한다.[^5]

### 공감과 위로

대화형 에이전트에 대한 체계적 문헌고찰에서는 쉬운 사용, 상호작용, 공감과 정서적 지원, 학습과 실행을 돕는 특성이 긍정적으로 언급되었다. 반면 연구별 결과와 평가 방식은 다양했고, 비용 효과나 안전·개인정보 영역은 상대적으로 덜 다뤄졌다. 의료 대화 서비스의 결과를 유료 운세 콘텐츠의 구매 만족도로 옮길 수는 없지만, 캐릭터의 따뜻한 말만이 아니라 사용자의 사정을 듣고 응답을 바꾸는 구조를 검토할 근거는 된다.[^6]

성신당에서 위로는 상황을 확인한 뒤 그 상황에 맞게 책임과 선택지를 다시 나누는 방식으로 구현한다. 예를 들어 수정이 계속된 이유가 상대의 요구 변경이라면, 이를 사용자의 완벽주의로 설명하지 않는다. ‘애썼다’는 말 뒤에는 원래 약속과 추가 요구를 나눠 적는 행동이 따라온다. 이 연결은 설계 판단이며 실제 독자가 감동했다는 관찰 결과는 아니다.

### 통제감과 실생활 사용

자기결정성 이론을 기술 설계에 적용하는 자료는 자율성·유능감·관계성을 사용 경험을 평가하는 관점으로 제시한다. 서비스 안에서 참여가 높아도 생활 전체에서 통제감을 잃는다면 같은 의미의 좋은 경험이라고 보기 어렵다. 성신당에서는 해석에 반대할 권리, 답변 초기화, 읽기 속도 선택, 저장 여부 선택을 구매 유도보다 앞선 사용자 기능으로 본다.[^7]

실행 의도 연구는 ‘무엇을 하겠다’는 목표만 두는 것과, 특정 상황에서 어떤 행동을 할지 정하는 계획을 구분한다. 이를 바탕으로 실행 카드에 상황·행동·관찰·어려울 때의 대안을 넣었다. 여기서 기대하는 효과는 읽은 내용을 생활에 적용하기 쉽게 만드는 것이며, 연구의 효과 크기를 성신당 사용자에게 그대로 적용하지 않는다. NCI의 해당 자료는 현재 갱신되지 않는 참고 자료임을 명시하고 있으므로, 고전적 개념의 설명으로만 사용했다.[^8]

### 구매 전후의 약속

Baymard의 디지털 구독 사용성 연구 소개는 서비스 설명, 상품 선택과 가입을 디지털 상품의 별도 과업으로 다룬다. 공개 소개만으로 특정 개선이 성신당의 전환율을 얼마나 올릴지는 계산할 수 없다. 성신당에서는 상품을 고르기 전에 차이를 이해하고, 구매 후 약속한 내용으로 바로 연결되고, 구독과 일회 결제를 구별할 수 있는지를 점검한다.[^9]

## 3. 공개 서비스에서 확인한 기대 수준

포스텔러의 공개 페이지는 여러 운세 방식, 상담·AI·만세력 등 서비스 진입점과 구체적인 생활 질문을 제공한다. 점신의 공개 웹 진입점에서도 일별 운세, 정통 사주, 궁합, 직업 등 사용 목적별 분류가 확인된다. 이는 이용자가 관심 있는 질문으로 빠르게 들어가고 싶어 한다는 시장의 제품 구성을 보여준다. 공개 목록만으로 각 유료 풀이의 개인화 수준이나 고객 만족도를 평가할 수는 없다.[^10][^11]

성신당에 적용할 차이는 콘텐츠 수 경쟁이 아니라 한 질문의 해결 과정이다. ‘일에서 왜 힘든가’를 선택한 사람이 직장·평가·요구 변경·자기 기준 중 어떤 조건이 실제 문제인지 좁혀 갈 수 있어야 한다. 다른 캐릭터를 열었을 때는 말투와 관점의 차이가 설명되어야 하며, 같은 이야기를 여러 목소리로 읽는 부분을 새 독립 진단처럼 포장하지 않아야 한다.

| 비교 항목 | 공개 자료로 확인한 범위 | 성신당의 적용 판단 |
|---|---|---|
| 질문별 진입 | 생활 주제에 따른 콘텐츠 분류 | 고민 6개를 별도 장면·행동으로 연결 |
| 여러 해석 방식 | 전통 방식·상담·AI 등 진입점 | 캐릭터 목소리와 계산 근거의 역할 구분 |
| 반복 이용 | 일별·월별·시기별 콘텐츠 | 일진마다 사용할 질문과 행동 제공 |
| 유료 가치 | 유료 전문·실제 구매 평가 미확보 | 경쟁사 점수·가격 우위를 임의로 작성하지 않음 |

## 4. 성신당에서 발견한 문제

가장 먼저 점수의 대상을 바로잡았다. 기존 `worth` 검사는 일부 표본에서 문장 차이, 근거 표현, 가격과 글 분량의 관계 등을 재고 있었다. 이런 검사는 편집 보조 지표로 쓸 수 있지만, 새 통합 풀이를 실제로 읽은 사람의 만족도는 아니다. 글을 늘리거나 강한 표현을 더해 점수를 올리는 것이 목표가 되지 않도록 새 평가표를 별도로 구성했다.

페이지 감사에서는 읽기 속도를 즉시 바꿀 명시적인 버튼과 페이지별 과업 평가가 부족했다. 결과 감사에서는 조언 문장은 있었지만 실행 상황과 확인 기준, 어려울 때의 대안, 다시 꺼낼 수 있는 형태가 일관되게 제공되지 않았다. 무료 요약이 유료 본문과 다른 편집 경로를 쓰고, 분석지에서는 상담 답변의 변화가 이어지지 않는 문제도 있었다.

일진은 점수와 전문 설명이 쉬운 실생활 질문보다 앞에 나왔다. 분석지의 ‘없는 것’이라는 표기는 상대적으로 약한 기운을 실제 부재처럼 읽게 할 수 있었고, 공유 링크 복사는 실패하더라도 성공으로 표시될 수 있었다. 이러한 문제는 감동적인 문장 추가로 해결할 수 없으므로 화면의 표시 순서와 동작을 함께 수정했다.

## 5. 적용한 가치 요소

| 가치 요소 | 구체적인 제품 동작 | 확인할 사용자 과업 |
|---|---|---|
| 개인별 구체성 | 십신·분포·자리와 고민에 맞는 장면 | 자기 경험과 닮은 대목을 설명한다 |
| 실제 상황 반영 | 장면 확인 후 이유를 선택하면 설명 변경 | 이유를 바꾸고 달라진 조언을 찾는다 |
| 반대할 권리 | 맞지 않는 해석 제외·답변 초기화 | 거절한 설명이 다시 나오지 않는지 확인한다 |
| 쉬운 표현 | 짧은 문장과 생활 비유, 전문 근거 펼침 | 핵심을 자기 말로 다시 설명한다 |
| 캐릭터 일관성 | 무료 대화와 본문의 동일한 해석 흐름 | 목소리가 달라도 근거와 조건이 유지되는지 본다 |
| 통제 가능한 읽기 | 바로 읽기·큰 글자 선택 | 기다림 없이 원하는 속도로 읽는다 |
| 완결 | 위로와 하나의 행동으로 마무리 | 결제나 추가 방문 없이 얻은 것을 말한다 |
| 실행 가능성 | 상황·행동·관찰·대안 카드 | 언제 무엇을 해볼지 정한다 |
| 재사용 | 실행 카드 수정·복사·브라우저 저장 | 다음에 사용할 내용을 다시 찾는다 |
| 연속성 | 열린 페이지 사이에 상담 맥락 유지 | 본문에서 분석지로 가도 수정한 방향이 유지된다 |
| 결제 투명성 | 기존 서버 가격·실제 범위·환불 조건 유지 | 총액·주기·포함 범위를 설명한다 |
| 실제 평가 | 페이지와 결과 평가를 별도로 수집 | 불편했던 지점을 기본 선택 없이 남긴다 |
| 불만 고객 포함 | 환불 이력도 가격 평가 자격으로 확인 | 환불해도 구매 의견을 남길 수 있다 |
| 관리자 판단 | 대상별 내부 점수·측정 시각·실제 응답 분리 | 낮은 항목과 원문 근거를 추적한다 |

바로 읽기 설정은 기존 연출을 삭제하지 않고 선택권을 추가한다. 큰 글자는 본문 중심으로 적용한다. 움직임에 대한 통제와 누르기 쉬운 조작부는 접근성 지침과도 연결되지만, 이번 구현만으로 전체 WCAG 적합성을 선언하지 않는다.[^12][^13]

## 6. 내부 점수의 산식과 의미

페이지는 목적 20, 이동 20, 복구 15, 읽는 속도 선택 15, 평가 수집 10, 페이지 종류별 항목 20으로 구성한다. 읽기 페이지의 마지막 항목은 재사용, 결제 페이지는 가격·환불·구독 조건, 나머지는 입력과 선택 부담을 본다. 각 항목은 0·1·2 단계로 검사하고 가중 합을 100점으로 환산한다. 이 가중치와 문턱은 연구에서 추정한 회귀계수가 아니라 내부 설계 선택이다.

통합 결과는 쉬운 본문 15, 근거 접근 15, 수정·거절 15, 경험 확인 장면 15, 실행 조건 20, 완결·가져갈 것 10, 읽을 순서 10을 사용한다. 문장 길이 85자는 편집 검토를 위한 내부 경계이며 한국어 학년 판정 공식이 아니다. 근거가 부족해 해석을 보류한 경우는 거짓 결론을 생성하지 않은 것으로 다루며, 결론 개수가 적다는 이유만으로 타당성을 낮게 평가하지 않는다.

문단별 점수는 문장 길이와 노출 전문 표현을 검사한다. 따라서 100점인 문단도 내용이 충분히 개인적이거나 감동적이라는 뜻은 아니다. 무료 대화와 일진은 과업이 다르므로 별도 보조 기준을 사용한다. 서로 다른 기준의 점수를 한 평균으로 섞어 구매 가치를 주장하지 않는다.

각 검사에는 근거 설명, 부족한 항목의 수정 방향, 관련 연구 링크가 붙는다. 관리자 화면은 기준 코드와 생성 시각을 보여주고, 검사 후 코드가 바뀌면 이전 점수임을 표시한다. 배포 환경에서 현재 소스 대조를 할 수 없으면 그 상태를 판정 불가로 남긴다.

## 7. 표본과 비교 범위

주 비교표는 합성 명식 30개와 고민 6개의 종합본 180개, 첫 합성 명식에서 캐릭터 20명·고민 6개·등급 4개의 조합 480개로 구성한다. 총 660개이며 모든 생년월일의 전수 검사는 아니다. 특히 캐릭터와 등급 점검에 첫 명식이 반복되므로 전체 평균은 시장의 고객 구성에 따른 평균이 아니다.

페이지 표에는 물리적 페이지 12개와 선언된 세부 화면 29개, 총 41개 점검 행이 있다. 경로와 세부 화면은 서로 중복되는 범위가 있어 41행 평균을 전체 사용자 여정의 만족도로 해석할 수 없다. 정적 소스 검사에서는 실제로 동시에 표시되는 조건부 상태나 결제 제공자의 외부 화면을 완전히 평가하지 못한다.

수정 전 주 비교표의 평균은 페이지 75.2점, 결과 80.5점이었다. 최종 수정 후 점검에서는 페이지 95.4점, 결과 94.6점으로 바뀌었다. 이 수치는 실행 카드·통제 기능·평가 기능 등 검사 항목의 변화이며 실제 사용자가 그만큼 만족했다는 결과가 아니다. 일진·분석지·무료 대화 540개는 별도 역할 기준으로 평가했으며 최종 평가표에 행별 근거를 제공한다. 페이지 최저점은 90점, 종합 결과 최저점은 80점이다.

부록은 무료 대화, 일진, 분석지 결과를 같은 합성 명식과 고민 조합으로 추가 점검한다. 주 비교표와 기준이 다른 항목 및 사전 점수가 없는 신규 점검은 분리해 표시한다. 결과별 CSV와 HTML에서는 낮은 항목과 실제 생성 본문을 대조할 수 있다.

## 8. 실제 사용자 점수

페이지 평가는 과업 성공 여부와 쉬운 정도를 묻는다. 쉬운 정도는 1~7점이며 100점 표시가 필요하면 `(평균−1)/6×100`으로 환산한다. SEQ의 7점 과업 용이성 접근을 참고한 한국어 자체 번역 문항이다. 원 도구의 규준, 검증된 한국어 척도, 구매 만족도 점수와 동일하다고 주장하지 않는다.[^14]

결과 평가는 이해·개인적 공감·위로·실행 가능성을 각각 ‘그렇다·일부 그렇다·아니다’로 받는다. 내부 관리자용 독자 지수는 이를 100·50·0으로 환산해 같은 가중치로 평균한 자체 지수다. 각 항목과 응답 수도 함께 보여주므로 평균 하나가 어떤 경험을 가리는지 확인할 수 있다.

가격 대비 평가는 별도 1~5점 선택 문항이다. 브라우저가 보낸 유료 플래그를 믿지 않고 서버의 구매 이력을 확인한다. 환불한 구매자를 배제하면 불만족 의견이 빠질 수 있으므로 환불 이력도 인정하되, 이를 콘텐츠 열람 권한으로 사용하지 않는다. 무료 이용자의 일반 평가와 구매자의 가격 평가는 섞지 않는다.

| 지표 | 계산·범위 | 해석하면 안 되는 것 |
|---|---|---|
| 페이지 용이성 | 실제 7점 응답의 평균과 분포 | 지불 의향, 매출 효과 |
| 과업 성공 응답 | 완료·일부·실패의 실제 응답 수 | 관찰자가 검증한 과업 성공률 |
| 독자 지수 | 네 문항의 자체 환산 평균 | 명리 정확도, 임상적 효과 |
| 가격 대비 평가 | 구매 이력 확인자의 1~5점 평균 | 전체 고객의 만족도, 재구매율 |
| 내부 체크리스트 | 코드·생성 본문의 규칙 충족 | 실제 사용자 예상 평점 |

모든 평가의 기본값은 비어 있다. 응답이 없는 대상은 ‘미측정’이며 내부 점수로 채우지 않는다. 화면과 결과는 버전·고민·캐릭터·범위별로 구분하며, 같은 브라우저의 같은 대상 응답은 최신 의견으로 갱신한다. 여러 브라우저 사용이나 자발적 참여 편향 때문에 응답 수를 고유 고객 수로 단정하지 않는다.

## 9. 실제 독자 검증 절차

콘텐츠 검증에서는 누구를 모집했는지와 어떤 과업을 주었는지가 중요하다. 내용을 읽고 좋았는지만 묻기보다 필요한 답을 찾고, 의미를 자기 말로 설명하고, 다음 행동을 고르게 해야 한다. 진행자가 해석을 대신 설명해 주면 실제 이해의 어려움이 가려질 수 있으므로 참여자의 자발적 반응을 관찰한다.[^15]

첫 회차는 사주 친숙도와 구매 경험이 다른 참여자를 섞은 형성 평가로 진행한다. 먼저 이름과 결제 없이 제공 범위를 이해하게 하고, 실제 자신의 정보 입력과 시각 미상 선택을 시도하게 한다. 이후 자신에게 맞는 대목과 맞지 않는 대목을 하나씩 고르고, 상담 이유를 바꾸어 조언이 실제로 달라지는지 확인하게 한다.

읽은 뒤에는 한 가지 행동을 고쳐 쓰고 다시 찾아보게 한다. 가격을 보여준 뒤 포함 범위와 결제 주기를 설명하게 하고, 그 가격에 비해 무엇이 남았는지 묻는다. 감동적인 말을 했는지 유도하거나, 눈물을 흘렸는지를 성공 기준으로 삼지 않는다. 실제 가격 평가와 향후 지불 의향은 구분해서 기록한다.

비교 평가는 같은 명식과 같은 고민을 사용하고 버전 순서를 바꾸어 제시한다. 단순히 문장이 다른지를 넘어, 더 구체적인 장면·명확한 행동·틀린 해석의 수정이 어느 쪽에서 쉬운지 평가한다. 빈 평가표에는 이해 재진술, 가장 일반적이었던 문장, 가장 개인적이었던 대목, 해볼 행동, 제시 가격을 남길 칸을 제공한다.

표본 수는 필요한 정밀도와 비교 설계에 따라 별도로 정한다. 관리 화면의 소표본 안내 경계는 운영상 주의 표시이며 통계적 검정력을 보장하는 수가 아니다. 실제 참가자를 모집하거나 고객에게 연락한 결과는 아직 없다.

## 10. 개인정보와 재사용

상담 답변은 브라우저의 실행 중 메모리에서 페이지 사이에만 이어진다. 새로고침이나 종료 후 다시 묻게 되며 서버나 브라우저 영구 저장소에 상담 이유를 별도로 보관하지 않는다. 직접 고쳐 쓴 실행 카드는 저장 버튼을 눌렀을 때만 해당 브라우저에 30일간 보관하고, 서버로 보내지 않는다.

평가 저장에는 이름·생년월일·상담 이유·공유 URL·자유 입력 본문이 포함되지 않는다. 중복 갱신을 위한 해시 키가 사용되므로 완전한 익명 통계라고 부르지 않는다. 평가의 보관 기간은 90일이며 관리자 인증이 필요한 경로에서만 집계를 확인한다.

공유 분석지에는 상담 답변을 반영한 개인적 이야기나 실행 메모를 자동으로 넣지 않는다. 무엇이 공유되는지 화면에서 구분해 알려준다. 사용자가 보고 있던 유료 본문 전체나 개인 메모를 공유 링크로 우회 공개하는 기능은 추가하지 않았다.

## 11. 남아 있는 판단

현재 개선은 명시적인 품질 공백을 줄인 구현이다. 캐릭터 20명의 서술이 서로 독립적인 명리 진단인 것은 아니며, 규칙 기반 문장은 같은 근거 구조에서 반복될 수 있다. 특정 생년월일을 넣었을 때 반드시 남다른 산문이 나온다거나, 실제 삶의 문제를 정확히 알 수 있다고 말할 수는 없다.

전문 근거 영역에는 전통 용어가 남아 있고 그 해석의 타당성은 전문가 검수가 필요하다. 자동 검사에서 80점 이상이 나왔다고 이 검수가 끝난 것은 아니다. 다음 개선 순서는 내부 점수의 최고점 만들기가 아니라, 실제 독자가 막힌 페이지와 일반적이라고 지목한 문장, 실행하지 못한 이유, 가격 대비 아쉬웠던 범위를 기준으로 정해야 한다.

브라우저 기능 검사는 합성 주문과 로컬 API를 사용한다. 실제 결제 제공자의 라이브 승인, 운영 고객의 구매 이후 사용, 환불 이후 평가 참여율까지 검증한 것은 아니다. 최종 검사 기록에는 정상 완료한 항목과 환경상 확인하지 못한 상태를 함께 남긴다.

## 12. 최종 구현 검증

2026-09-13 로컬 검증에서 관련 Python 테스트 181개가 통과했고, 최종 웹 코드의 TypeScript 타입 검사도 통과했다. 브라우저에서는 320·390·1280px의 종합 풀이와 캐릭터 결과, 경험과 다른 해석의 제거·초기화, 390px에서 확인한 이유의 반영과 분석지 왕복, 행동 카드 저장·새로고침·삭제, 평가 기본값 없음 등을 확인했다. 검증 중 발견한 상담 질문 중복은 형제 컴포넌트의 중복 키를 분리해 수정했다.

선언된 이동 대상 34개는 로컬 합성 명식·합성 주문으로 열어 검사했다. 관리자와 공유 화면은 마지막 수정 후 별도 재검사했고, 기록을 합쳐 제공한다. 관찰한 페이지 오류와 문서 가로 넘침은 없었다. 일부 이동 대상은 같은 화면의 별칭이거나 권한에 따라 다른 화면으로 이동한다. 예를 들어 결제의 중간 상태는 결제 선택 화면으로 돌아왔으므로 외부 결제 완료 상태를 검사했다고 세지 않는다. 결과 화면은 생성 본문이 나타난 뒤 검사했다. 관리자에서는 660개 통합 결과와 540개 보조 결과의 실제 표 로딩을 확인했고, 느린 자동 조회의 중복 요청과 넓은 연출 점수표의 모바일 넘침도 수정했다.

최종 내부 점수는 페이지 41행 평균 95.4점·최저 90점, 통합 결과 660행 평균 94.6점·최저 80점이다. 기준 미충족 항목은 행별로 남겨 두었으며 높은 점수를 만들려고 가중치를 바꾸지 않았다. 실제 독자·구매자 응답은 미수집이다. 따라서 감동, 개인적 적중감, 가격 대비 만족을 이 점수로 대신 주장하지 않는다. 운영 배포와 라이브 결제 검증은 이번 로컬 완료 범위에 포함되지 않는다.
