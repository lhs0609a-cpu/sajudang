# 1만 명 유입을 대비한 제품 취약점 감사

감사일: 2026-09-09 · 기준 코드: `85c1b69` · 감사 브랜치: `audit/journey-20260909`

**현재 상태를 ‘1만 명에게 안심하고 판매할 만큼 검증 완료’라고 판단할 수 없다.** 정상 입력의 생성은 안정적이었지만, 동시 계산의 일관성·구매 복원·환불·오류 복구에서 실제 결함이 재현됐다. 카피를 더 강하게 만드는 것보다 계산과 구매 신뢰를 먼저 복구해야 한다.

이번 감사는 실제 사람 1만 명의 생각을 흉내 내서 결제율을 만들어낸 것이 아니다. 실제 엔진으로 합성 입력 1만 건을 실행하고, 별도 API·브라우저 실패 시험과 소스 검토를 했다. ‘돈 아깝다’, ‘나와 안 맞는다’, 이해도, 이탈률, 결제율은 실제 사용자 조사가 없으므로 수치로 추정하지 않았다. 발견 목록은 시험한 범위의 결과이며 모든 취약점을 발견했다는 보증은 아니다. 운영 코드 수정·배포·실제 결제는 하지 않았다.

## 3. ‘팩폭이 안 맞는다’와 ‘돈이 아깝다’를 만드는 내용·화면

### 확인된 표현 문제

1. **명식의 숫자에서 실제 생활을 바로 단정한다.** 1993-11-25 여성·서울·시간 미상·돈 고민의 훅은 ‘정재가 0’이라는 계산 뒤에 ‘그래서 돈이 들어와도 이게 계속될까부터 셌소’, ‘들어오는 결이 고르지 않아서요’를 출력한다. 소득의 규칙성이나 그런 생각을 했는지는 묻지 않았다. 월급이 안정적이고 그런 걱정을 하지 않는 사람은 이를 반례로 느낄 수 있다. 계산 근거가 있다는 사실은 생활 단정의 정확성을 입증하지 않는다. 질문형 첫 문장을 고쳐도 뒤의 단정은 남아 있다. 근거: `seed/bank.json:862,874`, `hook-unknown-hour` 화면.
2. **사용자 비교처럼 들리는 근거 없는 서술이 있다.** 인장첩에 ‘20개를 다 채우려다 … 그만둔 사람이, 1개만 제대로 읽고 간 사람보다 남은 게 적었소’라고 고정 출력한다. 이 문구는 이용자 성과 집계와 연결되지 않는다. 관찰 사실처럼 쓰지 말고 ‘한 개를 읽고 실행해도 충분해요’ 같은 제안으로 바꿀 대상이다. 근거: `me/page.tsx:173`.
3. **무료 결과를 보려는 시점에도 이미지가 첫 화면 대부분을 차지한다.** 390×844 훅 화면에서 큰 장면 이미지 뒤로 핵심 질문·응답 버튼이 밀린 것을 캡처했다. 그림과 고양이는 몰입 장치가 될 수 있지만, 결과를 기다린 사람의 첫 보상보다 앞서 큰 공간을 차지하는 설계는 실험 대상이다. 이로 인한 실제 이탈률은 미측정이다.
4. **상품 이름보다 추가 효용이 덜 구체적이다.** 320px 상품 카드의 추가 내용은 ‘묻은 자리와 센 자리·뿌리가 있는가·바람이 부는 쪽’ 등이다. 초심자가 이를 보고 ‘내 고민에 무슨 답을 더 받는지’ 설명할 수 있는지 확인해야 한다. 가격·일회 결제·영구 열람은 화면에 표시되어 있다.

## 4. 종합점수의 취약점

현재 엔진 내부 검사 결과는 **71/100**, 세부 ‘나만의 것’ 43, ‘아픈 정확도’ 55다. 이 수치를 실제 고객 만족도나 사주 정확도로 해석하면 안 된다.

- `engine/worth.py`의 대표 표본은 생년월일 6개, 서울, 시간 있음, 대표 캐릭터 `wolha`, 성향 INFP에 치우쳐 있다.
- ‘아픈 정확도’는 돈·밤·사람 등 단어, 모호한 표현, 숫자 포함 비율을 센다. 실제 사용자에게 맞는지 비교하는 정답 데이터가 없다.
- ‘값만큼’은 가격과 컷 수·글자 수의 상관 등을 사용한다. 유용한 결론이나 실제 지불 의향을 직접 측정하지 않는다.
- API에는 71점을 ‘돈값은 한다’로 바꾸는 문구가 남아 있다. **현 관리자 UI는 이미 ‘자동 문장 검사’라는 제목과 한계 안내를 표시하고 있으며 이 등급 문구를 직접 출력하지 않는다.** 남아 있는 ‘아픈 정확도’ 등의 축 이름과 API 소비처를 정리할 필요가 있다.

권장 운영 지표는 분리한다: 계산 일관성/복구 성공률, 문장 품질 검사, 실제 이해도, 결제 후 효용 평가, 환불 사유, 구매 전후 기대 차이. 임의로 가중 합산한 하나의 ‘돈값 점수’로 출시 여부를 판단하지 않는다.

일진 점수도 별개다. `daily.py`는 기준 58에 용신 +26, 강한 오행 -14, 충 -20, 같은 일지 +8 등을 적용하는 내부 배치 점수다. 셈법은 화면에 제공되어 있다. 이를 그날 성공 확률이나 실제 운의 측정치로 확장해서 설명하면 안 된다.

## 5. 발견하지 않은 문제와 검사 한계

- 미결제 사용자가 `tier=all`을 요청해도 API가 free로 낮췄다. 완료 URL 직접 진입도 구매 완료로 인정하지 않았다.
- 2월 30일은 400과 구체적인 한국어 설명, 24시는 422로 거절했다. 출생 시각 미상은 실제 3기둥이었다.
- 320px의 진입·입력·훅·상품·내 첩 및 확인한 다른 너비에서 문서 가로 넘침은 없었다. 모든 화면·기기·키보드·보조 기술을 검증한 것은 아니다.
- 추천 결과가 빈 표본은 추가 시험에서 2/1,000건이었다. 무료 대체 인물을 이미 읽은 경우 등의 분기이며, 진열대 이동은 제공된다. 이를 서버 오류나 이탈자 2명으로 세지 않는다.
- 기존 1만 부하 시험과 이번 시험은 실운영 PG, SMS, 카드 승인/거절, 한국 모바일 네트워크, 실제 동시 결제 1만 명을 검증하지 않는다. 현재 단일 인스턴스·SQLite 배포 용량은 별도 운영 부하 시험이 필요하다.
- 얼굴·이미지 전체의 톤앤매너 및 애니메이션 적합성을 이번 감사로 재검수 완료했다고 말하지 않는다.
- 기존 여정 도구의 오래된 문구 일치 검사, 무료 잠금을 ‘stop’으로 세는 규칙을 실제 이탈률로 쓰지 않았다. 이번 도구는 별도 파일로 남겼다.

## 6. 수정 순서와 실제 사용자 검증

1. **확대 유입 전:** C01 동시 계산 분리, C02/C11 구독 소유권 및 환불 일관성. 구독 활성화는 이 회귀 시험 이후.
2. **구매 신뢰:** C03~C07, C12~C14. 오류 재시도·조회 실패 구분·영구 열람 복구·재발행 처리. API 성공 코드만 보지 말고 실제 화면 복구를 승인 기준으로 삼는다.
3. **결과의 정합성:** C08~C10과 생활 단정 문구. ‘계산된 사실 → 해석 가설 → 확인 질문 → 맞지 않을 경우’ 순으로 고친다. 첫 문장만이 아니라 조건별 본문 전체를 대상으로 한다.
4. **가격 설명과 분량:** 추가 입력 고지, 무료/한 명/전체 차이, 첫 결론 요약, 세부 근거 접기. 고양이는 입력 완료·결과 준비·행동 저장 같은 의미 있는 지점에 짧게 배치하고 핵심 버튼을 가리지 않게 한다.
5. **소규모 실제 과업 연구:** 초심자·명리 익숙한 사람·시간 미상·음력/해외·고령·안정적 월급자·실직/은퇴자·연애 중/비연애 등 서로 다른 조건을 포함해 모집한다. 한 명이 여러 조건에 해당할 수 있다. 합성 생년월일로 실제 사람의 사연을 대신하지 않는다.
6. **과업:** 처음 10초 뒤 서비스 목적 설명하기 → 입력 완료 → 무료 결과를 자기 말로 요약 → 맞지 않는 문장 표시 → 구매 시 더 받는 것/가격/자동 결제 여부 설명 → 구매 복원/환불 경로 찾기. 구매 의향과 실제 구매는 별도 기록한다. 연구 참여자에게 결제를 강요하지 않는다.
7. **운영 계측:** 화면 조회·체류·훅 응답·결제 이벤트는 이미 있다. 여기에 오류 유형·재시도 성공·복원 성공·환불 이유를 개인정보 없이 연결하고, ‘이해 어려움/사연 불일치/반복/가격/지금 필요 없음’을 선택 응답으로 수집한다. 중립 응답과 부정 응답을 합쳐 정확도라고 부르지 않는다.
8. **A/B 검증:** 기술 결함 수정 후 첫 질문/요약 위치/상품 비교를 각각 실험한다. 효과 크기를 미리 만들어내지 말고 실제 유입 기준선으로 표본 수를 정한다. 결제율과 함께 환불·불만·오류·결제 후 효용을 본다.
