# 1만 명 시나리오와 재방문 흐름 점검 — 2026-09-09

## 실제로 확인한 결제 장애

운영 `/api/sales-status`가 `ready:false, reason:seller_setup`을 반환한다. 정상 UI 경로에서는 판매자 설정이 완료되기 전 PG 결제창을 열 수 없다. API health의 payments_live=true만으로 판매 준비가 끝났다고 판단하면 안 된다.

이 상태가 계속된다면 1만 명이 유입되어도 정상 UI 경로의 결제창 진입·승인은 0명이다. 가격 화면 방문은 가능하다.

## 시뮬레이션의 의미와 결과

실제 고객 1만 명을 모집하거나 구매 행동을 측정한 결과가 아니다. `tools/current_funnel_sim.py`에 명시한 미측정 통과율로 1만 개 가상 경로를 각 시나리오별 생성했다. 기존 시뮬레이터의 가정값을 현재 화면 구성에 맞게 옮겼으며 삭제된 이름·성격 입력 단계를 제외했다. 5번의 응답과 무료 요약 버튼을 별도 단계로 계산한다. 세 경우는 신뢰구간이 아니며 중간 경우도 예측치가 아니다. 광고 채널, 재방문, 기기, 가격 반응의 차이와 상관관계는 반영하지 않았다.

고정 난수 시드 20260909를 사용한다. JSON의 expected_if_ready는 확률 곱의 기댓값이고 simulated_if_ready는 이번 난수 표본의 인원으로 서로 조금 다르다. 두 값을 섞어 보고하지 않는다. 모든 단계의 입력 확률과 결과는 funnel.json에 기록했다. 실제 결제 또는 운영 분석 이벤트를 발생시키지 않는다.

중간 가정의 단계별 인원: 유입 10,000 → 첫 버튼 5,532 → 고민 선택 후 4,818 → 생년월일 제출 후 3,592 → 시간 선택 후 3,238 → 첫 해석 2,975 → 5개 응답 완료 2,098 → 무료 요약 1,461 → 가격 613 → PG 196 → 승인 129. 이 수치로 실제 이탈 원인이나 디자인의 개선 효과를 입증할 수는 없다.

## 확인한 문제와 수정

- 응답 중 새로고침하면 첫 질문부터 다시 시작했다. 같은 명식·고민·해석자의 연속된 기존 응답을 복원해 남은 질문부터 이어간다. 모두 답한 상태면 무료 요약 버튼을 즉시 복원한다.
- 저장된 부정 응답을 다시 요청하는 해석의 misses에도 전달한다. 복원 시 기존 응답을 피드백 API에 다시 제출하지 않는다.
- 명식·고민·해석자를 바꾸면 이전 화면의 해석·완료 상태를 초기화한다. 서로 다른 상담의 응답을 가져오지 않는다.
- 응답 건너뛰기는 추가하지 않았다. ‘잘 모르겠소’ 중립 응답은 그대로 유지한다.

## 실제 전환율을 확인하는 기준

판매자 설정 해소 후 동일 기간·유입 집단에서 고유 방문자를 분모로, 무료 요약·가격·PG 열기·서버 승인 확인의 고유 인원을 각각 집계해야 한다. 클릭을 승인으로 세지 않고, 테스트 트래픽·중복 이벤트·재시도는 제외한다. 모바일 입력 완료율, 첫 해석 응답별 이탈, 부정 응답 비율, 가격→PG, PG 실패 이유를 함께 확인해야 카피와 품질 문제를 구분할 수 있다. 그 전에는 특정 구매율이나 개선 후 상승폭을 보장할 근거가 없다.

## 범위와 남은 점

1만 건 엔진 검사는 계산·리포트 구조의 합성 사례 검사다. 실제 사람이 해석에 공감하는지, 기꺼이 돈을 내는지, 동시접속 1만 명을 감당하는지는 검증하지 않는다. 기존 초상화 원본 잘림 및 정렬 검사의 실패도 이번 응답 복원 수정으로 해결됐다고 볼 수 없다. 판매자 정보 입력이 필요하며, 이를 임의로 작성해 결제 차단을 해제하지 않았다.
