## 2. 왜 프론트와 API 를 갈랐나

**Vercel 에 API 를 못 올립니다.**

```
sxtwl 은 3.12+ 휠이 없습니다.  Vercel Python 런타임은 3.12 입니다.
→ 소스 빌드가 필요하고, 빌드 도구가 없으면 실패합니다.
```

게다가 서버리스는 이 서비스와 안 맞습니다.

- **브레이크가 상태를 요구합니다.** 하루 결제 2건, 세션 릴레이 2명은
  요청 사이에 숫자가 남아 있어야 셀 수 있습니다.
- 공유 링크는 90일 살아 있어야 합니다.

그래서 API 는 **컨테이너 한 대 + 볼륨**입니다.

---

## 3. ★ 상태 — 이걸 틀리면 서비스가 조용히 망가집니다

`store.py` 는 세 백엔드를 같은 인터페이스로 씁니다.

| 순위 | 조건 | 쓰는 곳 |
|---|---|---|
| 1 | `REDIS_URL` | 여러 대로 늘릴 때 |
| 2 | `STORE_PATH` | **지금 배포. 한 대 + 볼륨** |
| 3 | 없음 | 개발·테스트 전용 |

**메모리로 배포하면 안 되는 이유**

```
공유 링크(90일)가 재시작마다 사라짐
하루 결제 2건 카운터 초기화  → 제한이 없는 것과 같음
세션 릴레이 2명 카운터 초기화 → 브레이크가 풀림
```

브레이크는 매출보다 앞선다고 문서에 적어 놓고, 배포에서 조용히 풀리면
그 규칙은 없는 것입니다. 배포 전에 반드시 확인하세요.

```bash
curl https://sajudang-api.fly.dev/health | jq .store
# { "backend": "sqlite", "durable": true, ... }   ← durable 이 true 여야 함
```

`durable: false` 면 **배포하면 안 되는 상태**입니다.

## 4. 환경변수

### API (Fly secrets)

| 이름 | 필수 | 값 | 없으면 |
|---|---|---|---|
| `CORS_ORIGINS` | ★ | 배포 도메인 쉼표로 | 브라우저가 막아 **화면만 빔** |
| `STORE_PATH` | ★ | `/data/store.sqlite` | 브레이크가 풀림 |
| `STATEMENT_LOG_PATH` | | `/data/statement_log.jsonl` | 응답 기록이 날아감 |
| `DATABASE_URL` | | postgres URL | 파일 폴백으로 돔 |
| `REDIS_URL` | | redis URL | SQLite 로 돔 |
| `TOSS_CLIENT_KEY` / `TOSS_SECRET_KEY` | | PG 키 | 결제를 **거절**(503) |

```bash
fly secrets set CORS_ORIGINS="https://sajudang-three.vercel.app" --app sajudang-api
```

### 프론트 (Vercel env)

| 이름 | 언제 읽히나 | 왜 둘인가 |
|---|---|---|
| `NEXT_PUBLIC_API_BASE` | **빌드 시점에 값이 박힘** | 브라우저가 부름 |
| `API_BASE` | **런타임** | 서버 컴포넌트(OG 미리보기)가 부름 |
| `NEXT_PUBLIC_ADMIN_DEFAULT` | **빌드 시점에 값이 박힘** | 좌측 관리자 레일 기본값 |

앞의 둘은 **둘 다** 필요합니다. `NEXT_PUBLIC_*` 만 두면 배포 후 API 주소를
바꿔도 서버 쪽이 옛 주소를 물고 있어 **미리보기가 조용히 깨집니다.**

### ★ 출시할 때 반드시 끄는 것 — 관리자 레일

좌측 레일은 32개 화면을 한자리에서 오가며 고치기 위한 도구입니다.
프로덕션 화면이 아닙니다 (docs/08 §5).

| `NEXT_PUBLIC_ADMIN_DEFAULT` | 새로 들어온 사람 | `?admin=1` 을 아는 사람 |
|---|---|---|
| 없음 또는 `1` (**지금**) | 레일이 보임 | 보임 |
| `0` (**출시 때**) | 안 보임 | 보임 |

출시 전에는 켜짐입니다. 시크릿창·다른 기기에서도 바로 보여야 확인이
되기 때문입니다. 출시 직전에 이렇게 끕니다.

```bash
vercel env add NEXT_PUBLIC_ADMIN_DEFAULT production   # 값: 0
vercel --prod                                          # 재빌드해야 반영됩니다
```

★ 사람이 직접 정한 것은 기본값을 이깁니다. 레일 머리의 **[숨기기]** 나
`?admin=0` 으로 끄면 `adminSet` 이 남아, 기본값이 켜짐이어도 다음 방문에
도로 켜지지 않습니다. 이 구분이 없으면 껐던 레일이 계속 되살아납니다.

```bash
vercel env add NEXT_PUBLIC_API_BASE production
vercel env add API_BASE production
vercel --prod        # NEXT_PUBLIC_* 은 재빌드해야 반영됩니다
```

## 5. ★ CORS — 가장 찾기 어려운 실패

```
서버는 200 을 줍니다.  브라우저가 막습니다.  화면만 빕니다.
로그에도 안 남습니다.
```

`CORS_ORIGINS` 에 배포 도메인을 넣지 않으면 이렇게 됩니다.
Vercel 은 도메인이 여러 개(프로덕션·프리뷰·브랜치)라 다 넣어야 합니다.

확인:

```bash
curl -s -o /dev/null -w "%{http_code}\n" -X OPTIONS \
  https://sajudang-api.fly.dev/v1/chart \
  -H "Origin: https://sajudang-three.vercel.app" \
  -H "Access-Control-Request-Method: POST"     # 200 이어야 함

curl https://sajudang-api.fly.dev/health | jq .cors_origins
```

프리뷰 배포까지 붙이려면 와일드카드가 필요한데 FastAPI 의
`allow_origins` 는 와일드카드를 부분적으로만 지원합니다.
프리뷰를 쓸 거면 `allow_origin_regex` 로 바꾸세요.

## 6. 배포 절차

### API

```bash
fly deploy --remote-only --app sajudang-api
```

`--remote-only` 는 Fly 의 빌더에서 빌드합니다. **로컬에 도커가 없어도**
됩니다. 이미지는 67MB.

이미지에 들어가는 것은 `seed/` 와 `services/api/` 뿐입니다.
문서·프론트·참조구현체·테스트는 `.dockerignore` 로 제외합니다.
**`reference/sajudang.html` 은 전 로직이 들어 있는 파일이라 서버 이미지에
넣지 않습니다.**

### 프론트

`main` 에 push 하면 Vercel 이 자동 배포합니다.
Root Directory 는 `apps/web`, npm workspaces 로 `packages/shared-types` 를
함께 가져갑니다.

## 7. 비용과 잠자기

```toml
auto_stop_machines = "suspend"
min_machines_running = 0
```

요청이 없으면 잠들고, 오면 깨어납니다. 첫 요청이 1~2초 느립니다.

트래픽이 붙어 이 지연이 문제가 되면 `min_machines_running = 1` 로
바꾸세요. 그때가 되면 Redis 로 옮기고 여러 대로 늘리는 것도 같이
검토해야 합니다.

---

## 8. 늘려야 할 때

지금은 **한 대**입니다. 다음 순서로 갑니다.

```
① REDIS_URL 붙이기          여러 대가 같은 카운터를 봐야 함
② DATABASE_URL 붙이기       statement_log 를 파일 → Postgres 로
③ min_machines_running = 1  잠자기 지연 제거
④ 여러 리전                 한국 사용자면 nrt 하나로 충분
```

**볼륨은 한 대에만 붙습니다.** 두 대로 늘리는 순간 SQLite 가 갈라지므로
①을 먼저 해야 합니다. 순서를 바꾸면 브레이크가 대별로 따로 세어집니다.

| 항목 | 왜 |
|---|---|
| Postgres | statement_log 가 아직 파일입니다. 응답이 쌓이기 시작하면 옮기세요. |
| Redis | 한 대라 필요 없습니다. 늘릴 때 ①번. |
| 결제 | PG 키가 없습니다. 키 없이는 결제를 **거절**합니다(503). |

| 모니터링 | `/health` 체크만 있습니다. 에러 추적기 미연결. |
| 커스텀 도메인 | `.vercel.app` / `.fly.dev` 그대로입니다. |

## ★ 계측 — 어디서 나가는지 보기

```powershell
$env:FUNNEL_KEY = '<fly secrets 에 건 값>'
.\dev.ps1 funnel
```

| | |
|---|---|
| `POST /v1/events` | 화면이 보냅니다. 열쇠 없이 열려 있습니다 |
| `GET /v1/funnel` | 읽기. **열쇠 필요**. 안 걸면 503 으로 닫힙니다 |
| `DELETE /v1/events` | 비우기. **열쇠 필요**. 배포 직후 시험분 치울 때만 |

```bash
fly secrets set FUNNEL_KEY=아무거나긴문자열     # 안 걸면 퍼널이 안 열립니다
```

### 안 남기는 것

생년월일시 · 이름 · 고을 · 이메일 · 전화 · IP · **chart_id**.

`chart_id` 는 생년월일시 해시라 같은 생일이면 같은 값이 나옵니다.
준식별자라 `events` 테이블에 컬럼 자체가 없습니다. 서버가 화이트리스트로
한 번 더 거르므로, 화면이 실수로 이름을 실어 보내도 기록되지 않습니다.

### 관리자는 세지 않습니다

레일이 `?step=` 으로 화면을 건너뛰기 때문입니다. 그대로 세면
"a6 직전대비 200%" 같은 값이 나옵니다 — 배포 직후 실제로 찍혔습니다.
`admin` 이 켜져 있으면 `track()` 이 아무것도 보내지 않습니다.

## ★ DB — 한 대짜리는 SQLite

```
DATABASE_URL = sqlite:////data/app.sqlite     # fly.toml [env]
```

컨테이너가 뜰 때 `entrypoint.sh` 가 `alembic upgrade head` 를 돌립니다.
실패해도 서버는 뜹니다 — 계산은 DB 없이도 되기 때문입니다. 대신
`/health` 의 `db.enabled` 가 false 로 남아 눈에 띕니다.

`models.py` 는 방언 중립입니다. Postgres 로 붙으면 예전과 같은 타입
(JSONB · UUID · BIGSERIAL · GIN)이 나가고, SQLite 에서만 갈아탑니다.

```powershell
.\dev.ps1 migrate-sqlite    # upgrade → downgrade → upgrade 왕복
```

### Postgres 로 갈아탈 때

```bash
fly secrets set DATABASE_URL=postgresql+psycopg2://...   # [env] 를 덮습니다
fly deploy --remote-only
```

시크릿이 `fly.toml` 의 `[env]` 를 덮으므로 파일을 안 고쳐도 됩니다.
★ SQLite 에 쌓인 것은 **따라오지 않습니다.** 옮길 것이 있으면
`statement_log` 부터 옮기세요 — 공감률의 원천 자산입니다.

★ SQLite 인 동안 워커를 늘리지 마세요. 쓰기가 직렬화되어 잠깁니다.
늘리는 순서는 Redis → Postgres → 워커입니다 (§8).
