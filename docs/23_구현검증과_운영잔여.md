# 구현 검증과 운영 잔여 · 2026-09-08

21번 설계와 22번 구현에 이어 실제 추가한 내용과 완료되지 않은 범위를 기록한다. 코드 구현, 자동 검사, 실거래, 전환 효과는 서로 다른 완료 조건이다.

## 이번 구현

- 인물 20명 × 고민 6종의 확인 질문 120개를 각각 작성했다. 인물별 말투를 적용하고, 기존 엔진에서 실제 계산한 관측값을 함께 표시한다. 경험을 단정하지 않고 맞지 않는 해석은 받아들이지 않아도 된다고 명시한다. 무료 해석·유료 리포트의 시작 질문과 인물별 마무리 행동에 연결했다. 기존 문장 은행의 모든 조건부 본문을 전면 재작성한 것은 아니다.
- 첫 화면 무료 가치 설명을 익명 브라우저에 50:50으로 고정 배정한다. 서버와 브라우저가 같은 배정 함수를 사용한다. 7일 관찰을 완료한 최초 노출 코호트의 구매자, 전환율과 95% 구간, 매출·환불·순매출을 관리자에게 표시한다. 가격은 동일하다. 갱신 매출을 신규 구매 전환에 섞지 않는다. 표본 확보 전 승자를 선언하지 않는다.
- 첫 진입 화면의 LCP·INP·CLS를 관측한다. 관리자는 브라우저별 최대값의 p75와 표본 수를 본다. 실제로 수집된 지표이며 실험실 점수를 꾸며 채우지 않는다.
- 정기결제 첫 등록·갱신에 계정 잠금과 영속 결제 저널을 적용했다. 같은 주기에는 같은 주문·멱등 키를 사용한다. PG 성공 뒤 로컬 저장이 실패해도 같은 주문을 복구한다. 응답 불명확과 카드 거절을 구분하고, 불명확한 응답을 카드 거절 횟수로 세지 않는다.
- 매일 03:20 KST에 실행하는 GitHub Actions 예약 작업과 전용 인증 API를 추가했다. 한 실행의 처리 시간을 제한하고 남은 배치를 이어 실행한다. 취소한 구독은 만료 뒤 카드 키를 폐기한다. 작업 키는 Fly와 GitHub Actions에 저장하며 소스나 로그에 남기지 않는다.
- 구매 내역에서 열람 전 전액 환불을 요청할 수 있다. 계산 오류 주장은 별도 검토 요청으로 접수하며, 관리자 확인 전 자동 환불하지 않는다. 관리자에게 주문·금액·사유를 표시하고 주문별 검토 메모를 받는다. 구매자도 검토 결과를 확인할 수 있다.
- 리포트와 종합 리포트 열람을 서버에서 기록한다. 환불과 같은 계정 잠금 안에서 자격을 다시 검사하고 유료 본문을 반환한다. 클라이언트의 `opened=false`로 열람 후 환불을 우회할 수 없다.
- 현재 이용 기간의 구독 주문을 전액 환불하면 카드 키와 자동결제도 종료한다. 과거 기간 환불은 새로 결제한 기간을 없애지 않는다. 환불 주문을 관리자 순매출 집계에서 제외한다.
- 라이브 정기결제에는 암호화 키와 `TOSS_BILLING_APPROVED=true`가 모두 필요하다. 이 값은 토스의 별도 자동결제 계약을 확인한 뒤에만 설정한다. 현재 계약 확인은 대기 중이다.
- 첫 무료 훅의 고민별 30문장을 경험 확인 질문으로, 후속 10문장을 구체적인 돌아보기 안내로 다시 썼다. 사용자가 경험을 부정했을 때 해석을 인정하도록 바꾸고, 동의를 예측 성공으로 포장하던 답변도 없앴다. 타인이 사용자를 나쁘게 평가한다고 지어내던 문장과 생활 리듬 구간의 자가진단 표현을 수정했다. 문구 버전을 공감률 ID와 캐시 키에 반영해 기존 문구의 응답 수치와 섞지 않는다.

## 아직 완료로 표시할 수 없는 것

1. **초상화:** 기존 파일의 상단 여백·잘린 머리 문제. 내장 이미지 생성으로 청암거사 복원을 두 번 시도했지만 두 결과 모두 1086×1448 RGB이고 배경이 실제 알파가 아니었다. 운영 에셋으로 교체하지 않았다. 생성 미리보기는 출력 폴더에 보관했다. 기존 정렬 도구 사용 여부에 대한 답변은 아직 받지 못했다. 위치 이동만으로 잘린 머리가 복원되지는 않는다.
2. **정기결제 라이브 활성화:** 운영은 일회성 결제 라이브 키를 쓰지만 구독은 비활성이고 등록 구독자는 0명이었다. 암호화·갱신 작업 설정을 준비했다. 별도 빌링 계약 확인 전 활성화하지 않는다.
3. **실거래 검증:** 사용자 카드로 결제·환불·갱신을 실행하지 않았다. 계약·테스트 결제 환경 또는 사용자가 직접 수행하는 실거래 확인이 필요하다.
4. **모든 조건부 본문의 전면 집필:** 이번에 새로 쓴 것은 120개 첫 질문과 인물별 마무리·확인 안내다. 기존 조건부 본문의 회귀·중복 검사를 수행했지만 전체 문장 은행을 새로 집필했다고 주장하지 않는다.
5. **실제 전환율:** 수집 장치는 구현했지만 운영 사용자 표본과 7일 관찰 기간이 필요하다. 결제율 상승·1만 명 실사용 만족도는 아직 관측하지 않았다.

## 운영 확인과 되돌리기

- 프론트는 `https://sajudang-three.vercel.app`, API는 `https://sajudang-api.fly.dev`다. main 푸시는 Vercel 배포를 트리거한다. API는 별도로 `fly deploy --remote-only`한다.
- 배포 뒤 `/health`의 영속 저장소, 무료 리포트의 `editorial.version=2`, 관리자 API의 비인증 거부, 정기결제 상태를 확인한다.
- 예약 작업은 직접 카드나 금액을 받지 않는다. 저장된 계약의 만기만 처리한다. 계약 확인 전 신규 라이브 등록은 닫혀 있다.
- 직전 API 이미지: `registry.fly.io/sajudang-api:deployment-01M205F6KGGMHGAWA7YZCJVY9C`. 직전 프론트: `sajudang-mlxl8o713-fewfs-projects-83cc0821.vercel.app`.
- 이전 API에는 계약 확인 플래그가 없으므로, 정기결제를 활성화한 뒤 롤백할 때는 신규 구독 등록 노출과 예약 작업을 함께 확인한다. 암호화 키를 임의로 회전하거나 삭제하지 않는다.
