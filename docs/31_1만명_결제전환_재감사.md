# 1만 명 합성 여정 및 결제 전환 재감사

검사일: 2026-09-09 · 대상: https://sajudang-three.vercel.app · API: https://sajudang-api.fly.dev

## 결론

현재 배포 화면의 정상 구매 경로는 결제 버튼이 차단되어 있다. 이 상태에서 정상 UI를 따라 들어온 1만 명의 결제 완료는 0건이다. 이는 구매 의향을 예측한 0%가 아니라, 결제를 시작할 수 없는 구성상의 차단이다. 이를 해결한 뒤의 전환율은 현재 자료로 산출할 수 없다.

운영 `/legal`의 사업자 정보는 모두 ‘아직 없음’이다. 웹은 `apps/web/lib/biz.ts`의 여섯 사업자 설정이 모두 있어야 `SELLABLE=true`가 된다. API의 `/v1/pay/config`는 enabled/live=true지만, 웹 `apps/web/app/pay/page.tsx`는 SELLABLE 조건을 추가로 확인한다. 상품 선택 후에는 결제 버튼 대신 ‘잠시 후 결제를 다시 시도해 주시오’가 나온다.

운영 웹 번들을 320·390·1920px에서 실행한 4개 여정 모두 재현했다. API 데이터는 격리 서버를 사용했고, 결제 준비 응답만 enabled=true와 테스트 클라이언트 키로 설정해 웹 차단을 분리 검증했다. 실제 PG 요청은 차단했다. 사업자 정보를 임의로 채우거나 판매 제한을 우회하지 않았다.

## 무엇을 실제로 테스트했는가

합성 인물 10,000건을 862.7초 동안 순차 실행했다. 명식·5단 훅·무료/유료 리포트·릴레이·일진·분석지는 각 10,000건, 스무 사람 종합은 500건 실행했다. 생성 예외 0건, 콘텐츠 가드 감지 0건이다. 별도로 20명 캐릭터 × 6개 고민의 120개 조합을 각각 83~84회 실행했고 선택 캐릭터 생성 오류는 0건이었다. 출생 시간 미상은 1,474건이었다.

원본 정합성 결과에는 15개 항목 중 ‘훅 일간 줄 = STAB_GAN’가 10,000건 실패했다. 확인 결과 실제 엔진은 `count_blade` 분기에서 일간을 포함한 다른 문장을 출력하며, 검사가 과거 문장만 기대하고 있었다. 원본 JSON을 보존했고, 현재 분기의 실제 일간 표시를 같은 10,000건으로 재검사해 실패 0건을 확인했다(`hook-branch-10000.json`). 나머지 14개 항목은 원본 실행에서 모두 통과했다. 검사 도구의 기준을 수정했으며 서비스 문구를 검사에 맞춰 바꾸지 않았다.

| 검사 | 실행 범위 | 결과 및 한계 |
|---|---|---|
| HTTP 부하 | 격리 로컬 API, 1,000회 방문, 동시 40개 작업, 사주·무료 해석 총 2,000요청 | 오류 0건, 17.93초. 사주 p95 756.84ms, 해석 p95 760.49ms. 운영 서버 성능 보증이 아님 |
| 결제 회귀 | 승인·거절·중복/동시 승인·소유권·금액·환불/접근권·전환 계약 | 94개 통과. PG 모의 응답 기반이며 실제 카드 승인이 아님 |
| 달력·사주 버전·훅 | 관련 회귀 테스트 | 106개 통과. 해석이 개인 경험에 맞는다는 증명은 아님 |
| 브라우저 정상 흐름 | 320px 중립, 390px 긍정, 390px 부정, 1920px 중립 | 4/4 상품 화면 도달, 4/4 결제 버튼 차단, 페이지 JS 예외 0건 |
| 브라우저 오류 복구 | 훅·무료 상세·상품 목록에 500 오류 주입 후 재시도 | 3/3 정상 복구. 첫 로컬 URL 재작성 실험은 테스트 장치 문제로 폐기하고 운영 URL 라우팅 방식으로 다시 검증 |

1만 명이 동시에 접속한 시험도, 1만 명의 사람이 읽고 구매 여부를 판단한 시험도 아니다. 합성 생년월일의 엔진 입력에는 프런트의 연령 제한 대상도 포함된다. 실제 구매 가능 고객 1만 명이라는 뜻이 아니다. 이번 브라우저 검사의 API와 분석 이벤트는 격리 서버로 보냈다.

## 운영 퍼널: 현재는 비율을 일반화할 표본이 없다

조회된 입장 코호트는 익명 브라우저 11개다. 전원 7일 관찰 기간이 끝나지 않았고, 기존 QA 방문이 섞였을 가능성이 있다. 11명의 독립적인 실제 고객으로 간주할 수 없다.

| 순서 | 관측된 익명 브라우저 | 직전 단계 대비 미도달 |
|---|---:|---:|
| 첫 화면 | 11 | — |
| 고민 선택 | 6 | 5 |
| 생년월일 | 4 | 2 |
| 출생 시간 | 3 | 1 |

이는 관측 시점의 미도달이며, 각 사람이 그 화면 때문에 이탈했다는 인과관계는 아니다. 보관 주문은 pending 2건이고 승인 주문은 없었다. 화면 d3 조회 1건을 결제 1건으로 세면 잘못이다. 결제 성공은 서버 승인 이벤트와 주문 상태로 집계해야 한다.

## 결과가 이상하거나 안 맞는다는 문제를 어디까지 검증했나

엔진 정합성은 입력과 산출된 기둥·용신·대운·문구가 일관적인지 검사한다. 사람의 인생을 맞히는 정확도와 다르다. 내부 강약 값이나 종합 해석을 구매 전환 확률·과학적 적중률로 바꿔 표시하면 안 된다.

다른 생년월일의 전문이 다르다는 사실만으로 충분한 개인화가 증명되지 않는다. 읽는 사람이 중요하게 느끼는 첫 문장과 구체적인 행동이 얼마나 반복되는지도 봐야 한다. 기존 시뮬레이터의 ‘잠긴 컷’, 선택 입력 없음, 릴레이 상한 같은 구조적 관측은 판매 오류나 실제 이탈 인원으로 세지 않았다.

이번 표본의 무료/유료 전문은 각각 10,000종, 종합은 500종으로 모두 달랐다. 반면 일진은 702종이고 가장 큰 동일 그룹은 100건이었다. 일진의 공유 자체가 오류는 아니지만, 매일 나만의 상세 해석을 기대하게 만드는 상품 설명이라면 기대 차이를 점검해야 한다.

추가 입력 요구는 합성 경로에서 3,446건 관측됐다(context 1,435·partner 1,464·cards 54·image 56·meet 387·blood 50). 이 수치는 도구의 임의 입력 완료율에 의존하므로 실제 사용자 이탈률이 아니다. 인물별 추가 입력을 결제 전에 설명하는지 확인할 후속 항목이다. 두 번째 릴레이의 `recommend`가 빈 경우도 268건 있었지만, 소스에는 별도 `forced` 추천 표시와 항상 보이는 ‘진열대로’ 버튼이 있다. 따라서 ‘268명 막다른 길’이라는 기존 도구의 표현은 부정확하다. 해당 268건의 실제 브라우저 이동까지 개별 검증한 것은 아니다.

실제 사용자 검증에서는 ‘맞음/틀림’ 한 문항 대신, 이해 못 한 용어·반박한 문장·무료와 유료의 차이를 자신의 말로 설명하는지·가격을 본 뒤 구매하지 않은 이유를 수집해야 한다. 화면별 이탈 로그만으로 이유를 확정할 수 없다.

## 수정 및 재검증 순서

1. 실제 사업자 정보로 웹 빌드를 다시 만들고 판매 가능 상태를 통합한다. 실제 PG에서 승인→서버 주문 반영→콘텐츠 열람→새로고침/복원까지 한 번의 검증이 필요하다. 현재 실제 카드 결제 검증은 완료하지 않았다.
2. 무료 상세를 요약 우선으로 줄이고, 가격을 확인할 수 있는 직접 경로와 응답 건너뛰기를 제공한다.
3. 19,900원으로 받는 추가 답변·예시·범위를 구체화한다. ‘아니오’ 피드백을 무시하는 인상을 해소한다.
4. 말투·조사·API 안내·모바일 문장 줄바꿈을 함께 정리한다.
5. QA를 제외한 코호트로 한 변경씩 비교한다. 주 지표는 7일 이내 서버 승인 구매자/유효 신규 방문자. 보조 지표는 무료 완료, 가격 확인, 결제창 진입, 승인 실패, 환불, 불일치 응답이다. 전환율 상승과 환불·불만 증가를 함께 확인한다.

‘몇 %까지 갈까’에 지금 제시할 수 있는 수치는 목표 환산뿐이다. **가정상** 1%면 1만 명 중 100명, 2%면 200명, 3%면 300명이다. 어느 수치도 이 서비스의 예측치가 아니다. 현재 코드에는 구 여정과 중복 이탈 가정을 쓰는 `tools/conversion_sim.py`가 있어, 그 출력은 이번 결제율 추정에 사용하지 않았다.

## 설계 제안의 참고 근거

- [NN/g: Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/) — 중요한 정보부터 보여주고 세부를 단계적으로 제공하는 원칙. 무료 상세 축약의 참고 근거이며 이 서비스의 전환 상승률을 보장하지 않는다.
- [NN/g: Explicit Differences](https://www.nngroup.com/articles/explicit-differences/) — 상품의 실질적 차이를 명시해 비교 판단을 돕는다.
- [Baymard: Checkout form fields](https://baymard.com/blog/checkout-flow-average-form-fields) — 단계 수뿐 아니라 실제 입력 부담을 줄이는 접근. 해외 쇼핑 조사 수치를 국내 사주 서비스에 대입하지 않았다.
