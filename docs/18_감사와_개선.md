## 1. 릴레이 쏠림 — popularity bias 재순위

### 무엇이 문제였나

3,000명 중 2,583명(86.1%)이 같은 캐릭터(삼거리 노파)를 1순위로 받았고,
20명 중 11명은 규칙이 아예 없어 **한 번도 추천되지 않았습니다.**
릴레이는 이 서비스의 연쇄 구조 자체입니다. 연쇄가 한 갈래로 수렴하면
스무 명을 만든 뜻이 없어집니다.

### 바깥에서 찾은 것

추천시스템에서 오래된 문제입니다(popularity bias). 정석 처방은
**관련도에서 노출 점유율을 빼는 후처리 재순위** — Abdollahpouri 외(2019),
xQuAD 기반 개인화 재순위. 모델을 안 건드리고 정렬 단계에만 붙습니다.

### 어떻게 적용했나

실시간 노출 카운터 대신 **미리 잰 도달률**을 씁니다. 규칙이 결정적이라
도달률도 결정적이고, 워커가 여럿이어도 결과가 흔들리지 않습니다.

```
점수 = 우선순위/100  −  λ × 인구 도달률  +  0.15 × 보완도
λ = 0.5 (seed/relay_rules.json · exposure_lambda)
도달률 측정·기록: .\dev.ps1 reach --write   (tools/relay_reach.py)
```

### 여기서 배운 것 — λ보다 규칙을 먼저 좁혀라

λ=1.0 을 그대로 넣으니 쏠림은 풀렸는데 **노파가 0.3%로 죽었습니다.**
간판 캐릭터가 사라지는 건 과교정입니다. 진짜 원인은 λ가 아니라 규칙이
넓은 것이었습니다 — `가장 약한 오행 ≤ 1.0` 은 인구의 **88.5%** 에 걸립니다
(`tools/probe_conditions.py` 로 4,000명에 재본 값).
문턱을 `== 0.0`(21.1%)으로 좁히니 "여덟 자리에 하나도 없소" 라는 훨씬
강한 근거가 되고, λ=0.5에서 노파가 제 몫 21.4%를 지키면서 나머지가 살았습니다.

★ **문턱은 감으로 정하지 마세요.** `tools/probe_conditions.py` 가 후보
조건이 인구의 몇 %에 걸리는지 먼저 재 줍니다. 규칙 파일은 건드리지
않습니다 — 문턱을 고를 때만 씁니다.

### 규칙 10 → 20개

규칙 없던 10명에게 성격에 맞는 조건을 줬습니다. `always` 로 아무에게나
걸리던 패선생·적혈랑도 조건을 받았습니다 — 누구에게나 걸리는 규칙은

## 2. 성향 4글자 — 리서치가 진단을 뒤집은 곳

### 처음 진단 (틀림)

`saju_axis` 가 항 개수가 다른 합을 비교합니다 — `real`(4항) vs `idea`(3항),
`logic`(4항) vs `feel`(3항). 항이 하나 많은 쪽이 구조적으로 이깁니다.
그래서 E 69% · S 73% · T 71% · J 57% 로 쏠린다고 봤습니다.

### 바깥에서 찾은 것 — 한국에는 정반대인 두 분포가 있다

| | ISTJ | INFP | 성향 |
|---|---|---|---|
| 정식 MBTI (한국 대표표본 19,070명, 2021 학술) | 최다 | 하위 | S·T·J 편중 |
| 16Personalities (한국 70,266명, 2021) | 4.3% (12위) | 13.4% (1위) | I·N·F·P 편중 |

한국에서 "MBTI 뭐야?" 에 답하는 사람은 거의 전부 **무료 16Personalities**
결과를 말합니다. 이 검사는 융 이론이 아니라 Big5 기반이고, 운영사 스스로
I·N·F 유형이 과다대표된다고 밝힙니다.

```
사용자가 적어낼 넉 자   E 48.7 : S 43.9 : T 32.7 : J 43.7
사주가 내는 넉 자       E 68.5 : S 74.1 : T 71.0 : J 59.0
                                        ↑ T/F 가 38%p 반대
```

즉 정식 MBTI 기준으로는 우리 축이 오히려 잘 맞습니다.
**틀린 건 축이 아니라 기준이었습니다.**

### 그런데 보정해도 안 됩니다 — 직접 넣어 재봤음

백분위 보정(composite index 연구의 표준 처방)을 구현해 돌렸습니다.

```
        어긋난 자리   0칸    1칸    2칸    3칸    4칸    2.5단 깊게
지금                5.6%  21.7%  36.1%  28.1%   8.5%     94.4%
보정 후             7.5%  24.7%  36.8%  24.8%   6.2%     92.5%  ← 거의 안 움직임
```

이진 축 넷이면 **넷이 다 맞을 확률이 잘해야 6%** 입니다.
계산으로 될 일이 아니라 말하는 방식의 문제였습니다.

08-27 재측정 (`tools/axis_spread.py`, 4,000명):

```
겹친 자리   0칸 8.2%  1칸 27.8%  2칸 37.4%  3칸 21.1%  4칸 5.5%
깊은 해석이 나가는 비율   35.9%     (전 94%)

사주가 내는 넉 자   E 69.1 : S 72.3 : T 70.1 : J 59.0
사용자가 적을 넉 자  E 48.7 : S 43.9 : T 32.7 : J 43.7
```

### 어떻게 적용했나

겹친 자리를 먼저 말하고(`MATCH`), 깊은 해석은 셋 이상 어긋난 사람에게만
갑니다(`GAP_DEEP_AT = 3`, 약 36%).

부수 효과 둘:

- 넷이 다 맞는 6%에게도 할 말이 생겼습니다. 전에는 단을 통째로 빼서
  **가장 드문 사람에게 침묵**했습니다.
- `GAP` 의 해석 8문장을 조건형으로 바꿨습니다.
  "드러나는 기질을 오래 눌러온 것입니다" 는 그 사람의 지난 일을 확인 없이
  단정하는 말이라 **절대 규칙 2 위반**이었습니다.

### 덤 — 입력값 자체가 흔들린다

MBTI 는 5주 뒤 재검사에서 39~76%가 다른 유형이 나옵니다.
이건 제품 서사에 오히려 맞습니다:
"여덟 자는 안 바뀌오. 그대가 적은 넉 자는 지난달과 다를 수 있소."

"불균등 분포는 콘텐츠 공간을 실제보다 작아 보이게 만든다."

## 4. 반복이 위험한 진짜 이유 — Barnum 효과

Forer(1949) 이래 반복 검증된 결과: 전원에게 **똑같은** 성격 기술을 줘도
평균 정확도 평가가 **4.3/5** 입니다. 한 사람은 5문장 중 하나를 받아도
자기 얘기라고 느낍니다.

다만 결정적 단서가 붙습니다 — **"개인화되었다고 믿을 때만"** 그렇습니다.
그래서 진짜 위험은 반복 자체가 아니라 **반복이 들통나는 것**입니다.
일진은 매일·다수에게 동시에 나가므로 캡처 비교가 가장 쉬운 자리라,
알림 채널을 붙이기 전에 손봐야 했습니다.

## 5. 공감률 — 점추정 대신 하한

두 가지가 겹쳐 있었습니다.

**작은 표본** — 52/100 과 520/1000 은 둘 다 52% 지만 확신의 크기가 다릅니다.
Wilson score 하한을 씁니다. 표본이 작으면 알아서 내려가고, 쌓이면 점추정에
붙습니다.

```
 52/ 100  점추정 52.0%  →  하한 42.3%
520/1000  점추정 52.0%  →  하한 48.9%
900/1000  점추정 90.0%  →  하한 88.0%
100/ 100  점추정  100%  →  하한 96.3%   ← 100%라고 단정하지 않습니다
```

**선택 편향** — 100건을 가장 먼저 넘는 문장은 **가장 많이 겹치는 문장**입니다.
그래서 `shown`(노출)과 `answer_rate`(노출 대비 응답률)를 함께 내려보냅니다.

★ 하한이 낮은 문장을 감추는 방법도 있지만 쓰지 않았습니다. 감추면 화면에
  남는 숫자가 전부 높아 보입니다 — 그건 또 다른 거짓말입니다.
  **감추지 않고 낮게 말합니다.**

구현: `repo.wilson_lower()` · `repo.agreement()`.
응답에 `rate`(하한) · `point`(점추정) · `shown`(노출) · `answer_rate` ·
`basis`("Wilson 하한 95%") 를 함께 실어 보냅니다. 무엇을 보고 있는지
알 수 있어야 합니다.

## 6. 근거는 보이되 규칙은 감춘다

`relay/page.tsx` 가 `근거 · 목 0.0 ≤ 1.0` 을 그대로 렌더하고 있었습니다.
`목 0.0` 은 근거라 보여도 되지만 `≤ 1.0` 은 **규칙의 문턱**입니다.
설명가능 추천 연구가 지적하는 지점 그대로입니다 — 블랙박스를 쓰는 주된
이유가 알고리즘 기밀 유지이고, 설명은 신뢰 보정 오류를 유발할 수 있습니다.

규칙 20개의 근거 문구를 전부 다시 썼습니다. 문턱이 새는 문구 0건.

여기에 더해 **응답 자체에서 분기표를 뺐습니다.** `rule_id` · `priority` ·
`reach` · `score` 는 내려가지 않습니다 (`relay.PUBLIC_FIELDS`).
근거는 그 사람의 명식이지만 어떤 규칙이 몇 점으로 이겼는지는 알고리즘입니다.

테스트 셋이 이 자리를 지킵니다:
`test_reason_never_leaks_the_threshold` (규칙 파일) ·
`test_rendered_reason_is_clean` (렌더된 문구) ·

## 1. 값이 두 벌이었습니다

컷을 늘리는 장치가 '추가 입력' 하나뿐인데 비싼 캐릭터들이 그걸 안

`engine/lens_cuts.py` · `seed/lens_cuts.json`. 22컷 · 문장 278개.
