조사·적용일: 2026-09-20. 범위: A1~A7, 무료 풀이 D0, 해석자 본문 C2, 결제 안내 C4.

## 2. 현재 코드에서 확인한 문제

1. A1: 고민의 답을 보기 전에 6글자·8글자·십신·대운과 반복적인 비유를 읽게 했다. 서비스 설명이 첫 가치 경험을 밀어냈다.
2. A2~A5: 입력마다 감정 문장, 근거 설명, 다음 화면 예고가 누적됐다. 이름은 선택 입력인데도 설명이 길고 이동 위치도 혼란스러웠다.
3. A4b: 선택형 성향 대조에 근거가 불분명한 희소성 수치와 피로의 원인 단정이 들어 있었다.
4. A6: 계산한 글자를 보여준 뒤에도 생활과의 관계를 설명하기보다 비유가 반복됐다. 계산 상세가 처음부터 열려 있었다.
5. A7: 긴 다섯 마디에 경험 확인을 반복 요구했다. 응답 뒤 자동 이동으로 읽는 속도를 시스템이 정했다.
6. D0: 자세한 무료 본문보다 구매 안내가 먼저 나왔다. 무료가 많아도 유료 인물의 전문성을 경험하기 전에 구매를 제안했다.
7. 20인 샘플 응답: 유료 인물 19명은 공통 풀이를 포함해 무료 항목이 20개였지만 고유 관점은 각각 1장만 무료였다. 청동자는 무료 전용이었다. 이 수치는 1993-05-15 10:20 여성, 각 인물의 첫 지원 고민으로 생성한 로컬 출력이며 실제 이용자 통계가 아니다.

## 3. A1~A7의 역할과 새 원고

화면 ID는 유지한다. 실제 본길은 A1 → A5 → A3 → A4 → A4b → A6 → A7이다. A2는 A3에서 여는 선택 별칭 화면이다.

| 화면 | 사용자가 받아야 할 답 | 적용한 내용 |
|---|---|---|
| A1 | 여기서 내게 무엇을 해주는가? | “잘해보려 했는데, 왜 같은 고민으로 돌아오게 될까.” 결과 세 가지와 설명용 예시, 무료 시작 버튼을 앞에 배치. 예시를 개인 결과로 위장하지 않음. |
| A2 | 이름이 왜 필요한가? | 별칭은 부르는 말에만 사용, 12글자 제한. 입력 후 출생 정보로 복귀. |
| A3 | 왜 출생 정보를 주는가? | 선택한 고민을 상단에 유지. 양력 날짜·성별·지역을 계산 목적과 함께 간단히 설명. 날짜 오류와 연령 제한 유지. |
| A4 | 시간을 모르면 못 보는가? | 정확한 시·분과 시간 모름 경로를 함께 표시. 오전/오후 되읽기. 모르면 시주 제외. |
| A4b | 성향 유형이 꼭 필요한가? | 선택 항목임을 명시. 성향 없는 경로 제공. 사주 계산값과 성격 진단을 혼동하는 문구 제거. |
| A5 | 내 질문을 알아들었는가? | 돈·일·사랑·사람·방향·휴식을 실제 고민 질문으로 표시. 선택 직후 해당 질문을 되짚음. |
| A6 | 제대로 입력됐고, 이제 무엇을 받는가? | 날짜·시간·지역과 실제 계산한 기둥을 확인. 첫 해석 3장 예고. 계산표·보정 내역은 펼치기. |
| A7 | 내 경험을 구체적으로 설명하고 쓸모 있는 것을 주는가? | ‘나의 장면 → 반복의 이유 → 오늘의 행동’ 3장. 한 장씩 수동 이동. 첫 장만 경험 확인. 아니라고 답하면 다음 설명을 수정. |

### A7의 구체성

첫 해석은 6개 고민 × 계산된 십신의 5개 관계 묶음으로 30개 장면을 가진다. 개인 이름만 바꾸는 문구가 아니다. 같은 고민이라도 대표 관계에 따라 장면과 강점·부담의 설명이 다르다. 다만 같은 분기인 사람은 같은 문장을 받는다. 1인 1문장의 생성형 상담이라고 홍보하지 않는다.

일의 예시:

- 책임을 보는 분기: 급한 일을 계속 맡고 퇴근 뒤까지 일이 따라오는 장면.
- 준비를 보는 분기: 공고를 저장하고 자격을 더 갖춘 뒤 움직이려는 장면.
- 자기 기준을 보는 분기: 도움을 청하기보다 혼자 야근해 끝내는 장면.

각 장면은 질문으로 제시한다. 출생 정보로 실제 생활 사건을 알아냈다고 단정하지 않는다. 근거 펼치기에는 어떤 관계를 읽었는지, 동률인지, 시간 미상인지 표시한다. 첫 장에서 경험이 다르다고 답하면 같은 주장을 강화하지 않고 실제 선택을 돌아보는 질문으로 전환한다.

무료 3장은 해석과 작은 행동까지 완결한다. 다음 무료 풀이로 이동할 수 있고, 여기서 분석지만 열 수도 있다. 무료 첫 해석을 읽으려면 결제해야 하는 구조가 아니다.

## 4. 스무 사람의 무료·유료 경계

유료 19명 공통 원칙:

- 기존 공통 무료 풀이를 줄이지 않는다.
- 인물 고유의 현재 고민 풀이를 유지하고, 설명에 필요한 고유 관점을 추가로 최대 두 장 연다. 총 2~3장 전문을 구매 제안 전에 읽는다.
- 각 인물의 `lc_{id}_ask2`는 종합·적용에 해당하는 핵심 장으로 유료에 남긴다.
- 서버에서 실제 생성된 핵심 장·추가 목차만 구매 안내에 노출한다. 조건 때문에 없는 내용을 판매 목록에 넣지 않는다.
- 무료 응답에는 잠긴 본문을 포함하지 않는다. 제목·일부 미리보기만 보낸다. 유료 본문은 기존 서버 구매 권한 검증을 통과해야 열린다.
- 가격은 서버의 해당 인물 단건 상품 가격을 표시한다. 구독은 단건처럼 표시하지 않는다.

## 5. 적용 파일과 검증

- `EntryFlow.tsx`, `entry-copy.ts`, `entry.css`: A1~A7 문구와 화면 위계.
- `EntryReading.tsx`, `engine/entry_hook.py`: 짧고 완결된 무료 3장, 경험 응답, 이어 읽기. 기존 API 클라이언트는 classic을 유지하고 새 진입 화면은 entry2를 요청한다.
- `engine/reading_offer.py`, `engine/report.py`: 20인별 경계와 실제 생성된 목차 계약.
- `CharacterReadingOffer.tsx`, D0·C2·C4: 고유 무료 전문 → 핵심 질문 → 일부 미리보기 → 가격·상품 확인.
- `test_entry_redesign.py`: 실제 명식으로 6개 고민, 시간 있음/없음, 20인 무료·유료 경계, 미구매 본문 미노출, 별칭 HTML 이스케이프, 거절 반영을 검사.

## 6. 출시 후 판단할 것

전환율 향상은 아직 검증되지 않았다. 배포 전 로컬 검증과 실제 성과는 구분한다.

기존 계측의 `screen_view`, `hook_shown`, `hook_answer`, `price_view`, `tier_pick`과 서버 결제 성공 기록으로 다음을 본다: A1→고민 선택, 입력 시작→계산 완료, A7 첫 장→마지막 장, 무료 해석→상품 확인, 상품 확인→실제 결제. 관리자 세션은 기존 제외 규칙을 유지한다.

구매율만 보지 않고 거절 응답·환불·유료 내용 불만도 함께 본다. 무료 고유 풀이를 세 장으로 늘린 것이 완독을 낮추는지는 별도로 확인한다. 우선 기존 대비 흐름을 검증하고, 이후 두 장/세 장 노출 실험을 한다. 신규 화면의 짧아진 분량을 자동 문장 점수 하락만으로 되돌리지 않는다. 점수용 비유를 다시 붙이면 원래 문제로 돌아간다.
